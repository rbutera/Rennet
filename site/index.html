Rennet

A review harness.

You stopped writing the code. You still have to answer for it.

The stakes

LLM-generated code has inflated pull requests everywhere, and review is the bottleneck. Cloud review tools die at enterprise procurement. Fully autonomous review is trusted by nobody. The first user is not a smuggler, it is the engineer who no longer writes code by hand and cannot honestly say they have read the PRs their agents open.

What it is

A local-first review harness. A changeset too big to hold in your head is rolled up into logical cohorts you can read from base principles up, its decisions surfaced, never hidden, never capped. The result lands as a normal GitHub review, or on your own branch as a batch handed back to a coding agent that Rennet then re-reviews only where it changed.

The proof

Local-first, no Rennet backend, no telemetry. It drives the coding harnesses already on your machine, on your own keys. And the human disposes: no auto-approve, no auto-comment, nothing another person sees without an explicit act of yours. That is a property of the wiring, not a promise in a prompt.

A coding harness points a model at your codebase so it can write. A review harness points models at a change so you can read. The harness does the structural work. You do the deciding.

What it is not

  • Not a bot.
  • Not a cloud service.
  • No account with anyone but GitHub.
  • No telemetry.
  • Does not comment on your behalf.
