Designer notes  /  what to weigh in on
1
Render the shape, not the markdown. Header band, distilled why, spine, capability grid, requirement rows. The raw files are always one keystroke away, never the default.
2
The spec is reviewable material. The same conversation cluster works on a requirement, a scenario, a task, or a why paragraph. A request-change on a requirement collates like any other disposition.
3
Coverage wires it to the diff. Each requirement shows “covered by N hunks · N tests” from the existing mapping; click jumps to the claiming hunk. Zero hunks renders an honest “unimplemented”.
4
New capabilities are add-green. A green edge on the card, matching the diff’s add semantics, so new versus modified reads without a word.
