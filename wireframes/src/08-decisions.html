Storage & state
One refill-on-read bucket per org, stored behind a RateStore interface. No timers.
bucket.ts L14-23store.tsproposal · What Changes
2
why · reconstructed
State advances only when a request arrives, so idle orgs cost nothing and there is no sweep to schedule. The interface keeps Redis out of the core.
Not taken: a timer-driven refill loop; a single shared global bucket.
Failure posture
Fail open on store error, bounded by a process-local fallback bucket at 5x the org limit.
rate-limit.ts L44-47PR bodyflagged · 1
why · reconstructed
A limiter outage must never become an API outage; failing closed turns every store blip into a 5xx storm. The local cap keeps a full outage from becoming unlimited scraping.
Not taken: fail closed; unbounded fail-open (the flagged disagreement).
