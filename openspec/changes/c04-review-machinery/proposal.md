# C4 — Review machinery: code-block, code-tabs, the line-comment editor, selection toolbar, rich text (#489)

## Why

INVENTORY §3 carries 47 `[ws:C4]` claims describing the load-bearing shared layer every review surface renders through: a single `code-block` for every code appearance in the product (chat tool output, board code elements, excerpt tabs, click-to-reveal panels — R24/R9), a `code-tabs` multi-site evidence viewer for elements citing several places at once (R23), one `LineCommentEditor` so Save/Delete/Request-Changes behave identically wherever a line comment opens, a `ProseSelectionLayer` selection toolbar for Comment/Request-Changes/Explain on board prose (R27/R28/R30), and a `rich-text` markdown-subset renderer that turns backticked terms, `path:line` citations, bullets, and normative-grammar bolding into real UI instead of raw markdown bytes (R45). None of it exists in `app-ui` yet: C1 landed the `review` store slice as a foundation ("the review surface (C3+) fills these shapes in"), and C3 built the frame that will host these components, but the components themselves are still spike-only, sitting behind the spike's `CodeCommentsProvider` — a `useAppStore`/`useShallow` shim whose every consumer reads through a phantom `store?.` guard (autopsy S3, fence rule 4) because the shim can return undefined in contexts the real store never will. C5 (board), C6 (diff), C7 (chat), C8 (exits) all render code and prose; without this change each one would either duplicate the machinery or block on it. C4 ports the PRESENTATION (JSX, layout, interaction mechanics) and rewrites the STATE onto the real `review` slice, so five call sites end up sharing one code path instead of five copies.

## What Changes

All in `packages/app-ui/src/review/` (new), on C1's data seam (`useCommand`/`useMutation` in `data/`) and the `review` store slice (`store/review.ts`, extended in place — not replaced). **Zero new dependencies**: `shiki`/`@shikijs/langs` and `lucide-react` are already `app-ui` dependencies (used by `syntax/shiki.ts`, `components/icon.tsx`); `react-markdown` is also already a dependency but this change deliberately does NOT use it (see Reconciliation 5).

- **`review/citations.ts` — the span-read seam, one resolution point.** Every citation hydration (a code-tabs anchor reveal, a rich-text citation click) reads the CAPTURED patchset through `patchset.readSpan` (`useCommand("patchset.readSpan", ref)`), never a filesystem read — `/api/source` (the spike's Next.js route) has no successor. B3 registered the command's shape but dispatch is contract-only (`packages/server/src/dispatch.ts` throws `"patchset.readSpan is not bound yet"`); every task, test, and DOM proof in this change runs over `MemoryBridge`-stubbed handlers, behind this ONE module, mirroring how C3 isolated the B9 gap behind `sidebar-data.ts`. When B4/B10 bind dispatch, `citations.ts` is the only file that changes.
- **`review/line-comment-editor.tsx` — the ONE editor.** Ported from the spike's `code-block.tsx#LineCommentEditor` (already a pure, callback-driven component: `lineLabel`, `initialText`, `hasComment`, `onCancel`, `onSave`, `onRequestChanges` — no store coupling to strip), extracted into its OWN module (Reconciliation 2) so `code-block.tsx`, a future board-excerpt caller, and C6's diff view can each import it without importing the rest of `code-block.tsx`. Delete (comment exists only), Cancel (Escape), Request Changes, Save; saving empty text clears. Callers wire `onSave`/`onRequestChanges` to `reviewActions.setCodeComment`/`clearCodeComment`/`stageAsk` directly — no adapter layer.
- **`review/code-block.tsx` — the one code surface.** Ported from the spike's `CodeBlock`, tokenized through the EXISTING synchronous `syntax/shiki.ts` (`detectLanguage`/`tokenizeDiffLine`), not the spike's separate async `lib/code-highlighter.ts` + runtime `createHighlighter` (Reconciliation 3) — `CodeView` (the diff surface, `components/code-view.tsx`) already proves this tokenizer at production scale, and reusing it means one syntax pipeline for the whole app instead of two. Header: file path, rendered line range (`L42` / `L42–L58`), Copy (1.5s "Copied" confirmation, silent no-op when the clipboard API is unavailable), and — right of Copy, per #492's placement ruling — the impl↔test flip (R41), shaped as an OPTIONAL `counterpart` prop matching `CodeView`'s existing `{ label, path, onView() }` contract verbatim (Reconciliation 4), so the same button concept behaves identically whether the code is a diff row or a cited excerpt. Sticky horizontal gutter; absolute line numbers from the block's declared start line; highlighted lines tinted; hover swaps a line number for `+`, click opens `LineCommentEditor` spanning the card's full width regardless of horizontal scroll; a commented line shows a persistent glyph instead of `+`; a line carrying a staged request-change ask reads danger red, a plain comment or cited line reads evidence green. Comments and asks read/write the `review` slice directly (`selectCodeComment`, `reviewActions.setCodeComment`/`stageAsk`) — no shim, no `store?.` guard anywhere in this tree.
- **`review/code-tabs.tsx` — multi-site evidence.** `CodeTabs` (quiet pill tabs over several `CodeBlock`s, tab strip hidden at one excerpt) and `AnchorReveal` (a row of `basename:line` chips; clicking fetches through `review/citations.ts` and shows the slice below, clicking the active chip folds it away). Both use `review/reference-chip.tsx` for the pill/chip markup instead of each hand-rolling its own (the spike duplicates this between `code-tabs.tsx`'s `TabPill` and `rich-text.tsx`'s inline chip rendering — unified here). `useCommand`'s per-key cache already dedupes identical reads, so a re-opened chip does not refetch — no separate cache layer. An unreadable citation says so in one honest line (the command's `error` state renders as text, never a silent empty block).
- **`review/reference-chip.tsx` — the shared `basename:line` chip.** One presentational component (label = `basename:line` via the existing `canvas/symbol.ts#basename`, full path on hover/title) used by both `code-tabs` and `rich-text`.
- **`review/selection-toolbar.tsx` — `ProseSelectionLayer`, mode union kept.** Ported from the spike, the `"toolbar" | "comment" | "comment-rc" | "revise" | "explain"` mode union is UNCHANGED (the packet's keep-list item) — floating toolbar above the selection (flips below near the viewport top), positioned inside the scrolling board so it travels with the anchored text, dismissed by Escape or an outside click. Comment/Explain/Request-Changes verbs open the same mini editor quoting the highlighted span; saving mints a quote-anchored thread and, for Request Changes, also stages an ask carrying the quote as provenance and claiming that thread (so it counts once, not twice). Rewired onto the `review` slice's extended quote-thread shape (Reconciliation 1) instead of `useCodeComments()` — the `draftHandlers` prop (Revise/Drop/Explain, for retired-draft-block review) is kept verbatim since it is host-supplied, not store-coupled.
- **`review/rich-text.tsx` — the R45 markdown subset, base tier only (Reconciliation 6).** Bold (`**text**` → real `<strong>`, never literal asterisks), bulleted paragraphs (every line starting `- `), normative-grammar bolding (SHALL/SHALL NOT/MUST/MUST NOT/WHEN/THEN/AND/IF/WHILE/WHERE), backticked terms as plain monospace (never boxed pills), and `path:line` citations as `reference-chip` chips wired to `review/citations.ts` for click-to-reveal (folds away on a second click) — "a deliberate markdown subset... not a general parser," ported from the spike's tokenizer (`FILE_REF`/`TOKEN`/`SPEC_KEYWORD` regexes, `parseRef`/`HydratedCode`/`InlineCode`). Does NOT include the spike's `QuoteHighlight` durable-highlight-and-tooltip overlay — INVENTORY tags that block `[ws:C5]`, not C4 (Reconciliation 7); `rich-text.tsx` renders plain prose today and C5 wraps it with the highlight layer when it lands.
- **`review/index.ts`** barrels the public surface (`CodeBlock`, `CodeTabs`, `AnchorReveal`, `LineCommentEditor`, `ProseSelectionLayer`, `RichText`, `ReferenceChip`, the citations seam types) for C5–C9 to import; `app-ui/src/index.ts` re-exports the barrel.

## Reconciliations against main (packet drift, recorded per the dispatch rule)

1. **The `review` store slice's `quoteThreads` shape is thinner than the spike's `QuoteComment`.** C01 landed `quoteThreads: Record<string, { anchor: string }>` — deliberately minimal, per its own comment ("the review surface (C3+) fills these shapes in"). The selection toolbar needs the real shape: a thread carries an exchange (`messages: { author: "user" | "orchestrator"; text: string }[]`), not just an anchor, and `kind?: "comment" | "explain"` (an Explain thread never raises the exit count). This change extends `ReviewState.quoteThreads`'s value type in place and adds `reviewActions.addQuoteComment`/`addQuoteReply`/`removeQuoteComment`, mirroring the spike's `CodeCommentsStore` surface but living on the real slice — the same discipline C01 documented as expected of the surface that fills the shape in.
2. **`LineCommentEditor` moves out of `code-block.tsx` into its own module.** The spike nests it inside `code-block.tsx` and imports it from there into `diff-view.tsx`. That import direction is backwards for this repo: C6 (diff view) must not depend on the whole `code-block` module just to reuse the editor. `review/line-comment-editor.tsx` is its own file; `code-block.tsx` imports it like any other consumer.
3. **`code-block.tsx` tokenizes through `syntax/shiki.ts`, not the spike's `lib/code-highlighter.ts`.** The spike's highlighter is async (`createHighlighter` from bare `shiki`, loading `@shikijs/langs` grammars on demand) and needs a loading-skeleton state. `syntax/shiki.ts` is already synchronous (`createHighlighterCoreSync`, nine grammars wired at module load) and already proves itself at production scale in `CodeView`. Reusing it means `code-block.tsx` needs no loading state and the app carries one tokenization pipeline, not two; the INVENTORY claim about a "pulsing skeleton while awaiting highlighting" does not travel — tokenization is synchronous, so there is nothing to await.
4. **The impl↔test flip (R41, #492) reuses `CodeView`'s existing `counterpart` prop shape.** `components/code-view.tsx` already ships this exact feature (`counterpart?: { label, path, onView() }`) for diff rows, built ahead of this change for a different surface. Rather than inventing a second shape, `code-block.tsx`'s flip button takes the identical prop contract — one concept, one shape, two renderers.
5. **`rich-text.tsx` does not use `react-markdown`,** even though it is an installed `app-ui` dependency (used today by `components/prose.tsx` for the PR-body/handoff-draft renderer — a different, general-purpose surface, untouched by this change). R45 is explicit that the review prose pipeline is "a deliberate markdown subset... not a general parser": it must render citation chips wired to `review/citations.ts` and bold normative-grammar keywords, neither of which a generic markdown AST renderer does out of the box. `Prose` (`components/prose.tsx`) and `review/rich-text.tsx` solve different problems and both stay.
6. **`review/citations.ts` is the single resolution point for the B3-absent span-read binding** (packet's own framing, mirroring C3's `sidebar-data.ts` for the B9 gap). `patchset.readSpan` is registered in the protocol (`codeRefSchema` in, `{lines, contextBefore, contextAfter}` out) and covered by a commands-registry test, but `packages/server/src/dispatch.ts` throws on it today (`"patchset.readSpan is not bound yet (B4/B10 bind dispatch)"`). Every citation-resolving path in this change goes through `citations.ts`; production renders the command's honest `error` state (a citation "that cannot be read... says so in one honest line") until B4/B10 bind it, and tests supply `MemoryBridge` handlers. When dispatch binds, `citations.ts` is the only file that changes.
7. **The spike's `rich-text.tsx` mixes two INVENTORY workstreams; this change ports only its C4 half.** INVENTORY's "Board prose and reading affordances" and "Selection controls on board prose" sections are `[ws:C4]`; "Durable quote highlights and threads" (the `QuoteHighlight` component, the highlight-click tooltip, reply input, overlap resolution) is `[ws:C5]`, a separate section entirely. `review/rich-text.tsx` ports the base rendering pipeline only — bold, bullets, spec keywords, backtick mono, citation chips — and leaves quote-highlight rendering to C5, which wraps this component's output.
8. **`CodeCommentsProvider` and its `store?.` phantom guards do not travel**, per the packet and fence rule 4. Every C4 component reads the `review` slice directly through `useRennetStore`/the slice's selectors — never through a shim that can be `undefined`, and never through optional chaining on a value the real store guarantees.
9. **The spike's `/api/source` route has no successor.** Every "fetch the real lines" claim in INVENTORY (code-tabs' `AnchorReveal`, rich-text's citation reveal) binds to `review/citations.ts` → `patchset.readSpan` instead.
