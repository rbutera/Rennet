# C10 — Settings & the Archived surface: the route, the four pages, environment cards, and honest provenance (#489)

## Why

INVENTORY §8 carries **92 `[ws:C10]` claims** describing the Operate-side config surface: Settings as a full-view takeover that leaves by back-arrow or Escape (chat and board stay mounted so their state survives the visit), split into four pages listed in a left nav — **Environments, Appearance, Keyboard Shortcuts, Projects** (#476) — plus the **Archived** main surface, its own `/archived` route with search, sort, and unarchive.

None of this shape exists on `main`. Two things stand where C10 must build:

1. **`packages/app-ui/src/components/settings-screen.tsx` — one 1,137-line file.** It backs the OLD model (Global / Repo / Keyboard / Pairing tabs) against the real `settings.get` projection. It is the autopsy S2 sin repeated verbatim: four screens in one file, the very pattern the spike's `settings-view.tsx` (1,687 lines) was autopsied for. C10 replaces it with a `settings/` **directory** — one module per page, each a route target, no `useState`-shadowed "page" living inside a monolith.
2. **The route is a stub.** `routes/app.tsx` mounts an interim inline `SettingsScreen` (renders `Settings — {page}` and the scheme string) at `ROUTES.settings` (`/settings/:page`); `ROUTES.archived` mounts an `<Interim screen="archived">` placeholder. Both are placeholders C10 fills.

The spike's layout is far richer than the old file: Environments is a list of **host cards**, each carrying a daemon meta line, a **Source Control** detection section, an **Agents** section, and a **Review** model-mappings dialog; Projects carries identity + glyph grid, worktree naming with token preview, repository visibility/promotion, a "Runs on" detected fact, an **Issue Tracker** section, and inline guidance rules. C10 **ports that presentation and rewrites every value** onto `settings.*` command projections read through the C1 data seam (`useCommand`/`useMutation`), never off a fixture. The spike's `lib/settings-data.ts` fixture **dies entirely** — but its `{ value, layer }` provenance shape is a **keep** (it is a product feature: every layered value names the rung it resolved from). B10 serves those projections for real; until it lands, C10 wires them through the seam over **`MemoryBridge`-stubbed handlers**, exactly as C4 isolated `patchset.readSpan` and C3 isolated `sidebar-data.ts`.

C10 is **blocked by C3** (the shell/route frame that hosts the takeover) and, for live values, **B10** (the settings engine + `client-settings.json`/`daemon-settings.json` file split). MemoryBridge-first is the discipline: provenance chips render and edits persist **to the bridge** now (testable, never a hollow pass); real `client-settings.json` persistence and real host/tool/harness detection are isolated in one clearly-labeled deferred cluster.

## What Changes

All in `packages/app-ui/src/settings/` (new directory) and `packages/app-ui/src/archived/` (new directory), on C1's data seam and the existing route table. The old `components/settings-screen.tsx` and its `.dom.test.tsx` are deleted; the interim route wrappers in `routes/app.tsx` are replaced with the real screens.

- **`settings/settings-screen.tsx` — the route shell, never a `useState` page switch.** A full-view takeover that renders over the whole shell **including the chat column**, with chat and board kept mounted underneath so their state survives (claim: `shell.tsx` cooperation). Header carries a back-arrow, an `esc` key hint, and leaves on Escape or back to the prior surface. The active page comes from the **route param** (`/settings/:page`), and the Projects scope from **`?project`** — not a shadowed local `useState`. A left nav lists the four pages with icons. This is the explicit structural fix for autopsy S2: **a screen is a directory, a page is a route, not a variable.**
- **`settings/environments/` — the Environments page.** "This Machine" (local, never removable) plus remote host cards, each a real card: OS glyph (macOS/Linux/Windows, WSL = Windows mark + mono `WSL` chip) via a ported `lib/os-glyphs.ts`, name (inline-rename, Enter commits / Escape cancels / empty keeps old, flowing through to the sidebar host-group header — one hosts state), address-or-`Local` chip, a daemon meta line (version when reachable; "Not connected — daemon unreachable, version unknown"; "last seen running … v<n>" for a previously-seen host), Reconnect (unreachable only), Update Daemon (that host has an update only), and Remove (remote only, opening the one sanctioned destructive confirmation naming the projects/sessions it takes and stating the machine is untouched). Section header carries its own **Add Environment** button (second entry point beside the sidebar's).
- **`settings/environments/source-control.tsx` — detection on the host it belongs to.** No Providers page; each card's Source Control section lists that host's VCS/forge tooling as rows sharing one shape: official mark, tool label, tool's own version line (absent when undetected — no guess), a status chip (Available / Not Authenticated / Not Installed / Unreachable), an honest one-line helper naming the exact fix command (backticked → code), and an enable toggle. GitHub rides `gh`, GitLab rides `glab`, Bitbucket takes an API token, Azure DevOps does not appear (#483/#484). **No OAuth-shaped connect ceremony anywhere** (Rule Zero). A disconnected host shows one honest line ("Connect <host> to detect its tooling.") instead of fake rows. The GitHub mark scheme-swaps black/white; the others read on both.
- **`settings/environments/agents.tsx` + `model-mappings.tsx` — Agents and review roles.** An Agents section (same row shape as source-control) lists detected coding harnesses; disabling one rules it out of reviews without uninstalling. A Review section exposes Model Mappings and is absent when no agents were detected; Edit Mappings is inert until an agent is enabled and says so. The mappings dialog is a table of review roles × two columns (Dual Harness / Single Harness): **the column headers ARE the review-mode switch** (selected header carries the tick, the other dims/locks — no separate Review Mode row); Dual is unavailable until both agents are enabled (hover says which agent unlocks it); losing the second agent settles Single regardless of prior click; Single auto-detects its provider (preferring Claude) and names it in the subheading. Each role names its models + effort with an editable cell opening a searchable model picker; a role that doesn't run in a mode renders an em dash; a changed role gains Reset to default. Roles: Orchestrator, Context-Map Workers, Confirmation Worker, Lens Drafters, Flagged Second Seat, Adjudication, Post-Process Pass, Utility (#460/#464).
- **`settings/appearance.tsx` — the Appearance page.** Scheme as a light/dark/system segmented control; "system" resolves through `matchMedia` and re-applies on OS change (ported `appearance-sync.tsx`). Theme pack row (live-applying pills, ported `lib/theme-packs.ts`) and a **separate** code-theme row (live-applying pills, ported `lib/code-theme.ts`, independent of the interface theme, with "Follow scheme" resolving to the current scheme's variant). Changing the code theme re-highlights every code surface including the diff (`review/code-block.tsx`, `components/code-view.tsx`). The resolved scheme stamps `data-scheme` + the `dark` class on the root; the theme pack stamps `data-rn-theme` (default pack clears it).
- **`settings/shortcuts.tsx` — the Keyboard Shortcuts page.** Lists every named command with its binding, filterable by name; Escape in the filter clears the filter before it can close settings; each row exposes a Change control on hover (the remap *mechanics* are C11 — this page shows and routes); an empty filter result names the query that matched nothing. Registry includes Search ⌘P, Command Menu ⌘K, New Chat ⌘N, Toggle Sidebar ⌘B, Toggle Chat ⌘J, Settings ⌘, (R7). This is the destination **Help → Keyboard Shortcuts** (a C3 popover) navigates to.
- **`settings/projects/` — the Projects page.** Scopes to one project through an inline picker grouped by environment, following the active project by default (resolved from `?project`). Identity (display name with `org/repo` placeholder, Reset restoring the default, clearing-on-blur restoring the default, a project-glyph radio grid applying live to the sidebar via a ported `project-icon.tsx`). Worktrees (location directory + naming pattern with insertable `{project}`/`{branch}`/`{pr}`/`{user}`/`{date}` tokens and a live path preview flattening branch slashes to dashes). Repository (Review Context local vs git-visible with its provenance chip; promotion state; **"Runs on" as a displayed detected fact with provenance chip + host glyph, no editable override on the surface** — R22 amendment). Issue Tracker (github/jira/linear/none each with a provenance chip; scout pick lands "detected", user pick lands "global"; GitHub rides `gh` and exposes no fields; JIRA/Linear expose project key + base URL + the **name** of the token env var, never the token; switching to a REST tracker seeds the conventional env-var name; switching away drops fields; no-tracker reads "none"; Escape in a field blurs, never closes settings). Guidance (repo rules each with a severity chip, inline edit with a severity segmented control + Save/Cancel/Delete, Enter saves and Escape closes only the editor, an Add Rule control at the bottom, empty text refused).
- **`archived/archived-screen.tsx` — the Archived surface (its own route, not a settings page).** Its own main-surface `/archived` location, leaving by back-arrow or Escape with an `esc` hint; header shows the archived count when there is one; an empty state says so and how sessions get archived; searchable by session title or project name (Escape clears the search before closing the view); sort by recent/project/title via a radio group (recency parses the fuzzy sidebar times "now"/"1h"/"2d"/"3w" into a real order); each row carries target icon, title, reviewed tick, time, and a project chip with the project's glyph, plus an Unarchive control on hover/focus; selecting a row opens that session; an empty search result names the query.
- **`settings/data/` — the settings command seam (the single resolution point for B10-absent projections).** Every value reads/writes through `useCommand`/`useMutation` over `settings.*` commands. The existing commands (`settings.get`, `settings.setAppearance`, `settings.setKeybinding`, `settings.setRepoVisibility`, `settings.setRepoLocus`, `settings.pinRepoValue`, `settings.resetRepoValue`, `settings.guidance`) bind live; the projections the old model never had (environments/hosts, source-control detection, agents detection, model mappings, project glyphs, worktree pattern, issue tracker) are read through this seam over `MemoryBridge`-stubbed handlers until B10 serves them. The `{ value, layer }` provenance shape is preserved as the projection contract. **`lib/settings-data.ts` (the spike fixture) has no successor** — it is deleted, not ported.
- **`settings/provenance-chip.tsx` + `settings/backing-file.tsx`** — the two shared presentational atoms every section reuses: the provenance chip naming the resolved rung (builtin/detected/global/repo) and the monospace backing-file caption (`client-settings.json`, `daemon-settings.json`, or `.rennet/`).
- **`routes/app.tsx`** — replace the interim `SettingsScreen` with `settings/settings-screen.tsx` and the `<Interim screen="archived">` with `archived/archived-screen.tsx`. `app-ui/src/index.ts` re-exports the new public surface; the old `SettingsScreen` export is retargeted.

## Reconciliations against the packet and `main` (recorded per the dispatch rule)

1. **"Settings + Help" — Help is not a C10 surface.** The packet Objective names "Help = Documentation / Keyboard shortcuts / Report an issue," but INVENTORY §8 carries **zero** Help claims. The Help control is a **popover in `app-sidebar.tsx`, tagged `[ws:C3]`** (INVENTORY §2, "Update, Help, Settings": Documentation / Keyboard Shortcuts / Replay Tour / Report an Issue; "Contact support" absent), already landed. C10 owns the **destinations** Help links to — the Keyboard Shortcuts page is the target of "Help → Keyboard Shortcuts" — not the popover. No Help page is built; the tasks verify the nav target exists.
2. **Settings is four pages; Archived is a sibling route, not a fifth page.** Claim 577 fixes the four (Environments, Appearance, Keyboard Shortcuts, Projects); the Archived claims (677–687) all cite `components/archived-view.tsx` and `app/archived/page.tsx` — a **separate main surface** with its own route, not a settings page. The dispatch listed "Archived" among the pages loosely; C10 builds it as its own `archived/` directory + `/archived` route.
3. **An existing `settings-screen.tsx` (old model) is replaced, not extended.** `main`'s 1,137-line file implements Global/Repo/Keyboard/Pairing against `settings.get`. Its live bindings (appearance, keybindings, repo visibility/locus, guidance, GitHub account rows) are **salvaged into the new page modules** — the wiring is real and correct — but the file itself dies so the directory structure replaces the monolith (the S2 fix). Its `.dom.test.tsx` is superseded by per-page DOM tests.
4. **The route already exists; only the screen is a stub.** `ROUTES.settings` (`/settings/:page`) and `settingsPath(page, project)` (writing `?project`) already ship in `routes/url.ts`. C10 does **not** add the route — it fills the screen and reads the param, satisfying "settings is a route" without touching the router table beyond the mount swap.
5. **B10-absent projections stub through one seam, like C4/C3.** The environments/detection/agents/mappings/tracker/glyph/worktree projections are not in the protocol's `settings.*` set today. They read through `settings/data/` over `MemoryBridge` handlers; provenance chips + persistence-to-bridge are testable now; the honest deferral is the isolated cluster below. This mirrors C4's `citations.ts` (`patchset.readSpan`) and C3's `sidebar-data.ts` precedent — no new dispatch binding in C10.
6. **"Update button-only."** No auto-update anywhere: "Update Daemon" is a button that appears only when that host has an update (claim 594), and the sidebar's Update control is C3's. C10 renders the button and its visibility rule; the update *mechanism* is out of scope.
7. **"Runs on" carries no override control** (claim 658, R22 amendment) — it is a displayed detected fact with a provenance chip and host glyph. This is not a gate: there is simply no editing affordance on this surface, by design; execution-locus editing lives in the Repository section's existing `settings.setRepoLocus` path, which is a different, real control.
8. **`settings-data.ts` dies; provenance shape lives.** The fixture (`keyCommands`, `projectSettings`, `IssueTrackerSettings`, `UNSET_TRACKER`, etc.) has no successor file. Its `{ value: T; layer: SettingsLayer }` shape is preserved as the seam's projection contract — the product feature (every layered value names its rung) survives, the demo data does not.
