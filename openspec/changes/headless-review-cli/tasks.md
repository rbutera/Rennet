## 3. Progress, the document, reattach, exit codes (D6, D7, D8, D9)

- [ ] 3.1 `foldPreparationLines(previous, next, elapsedMs)` in `cli-review.ts`: pure, returns the lines a record transition prints (capture step; per lane status with verdict or reason; per seat `latest.text` change, named by `seat` and `provider`). Controls: a `queued` to `running` transition with a seat line prints two lines; an unchanged record prints none; the Flagged lane's three seats print under one lane name; a `failed` lane prints its reason once
- [ ] 3.2 The printer: poll `session.list` at 400 ms while the row's preparation is `capturing` or `drafting`; `onFrame` prints `lensDraft` frames for the review id as `<lens>  wrote <n> element(s)`; every line `[+<s>s] ` prefixed on stdout. Control: a scripted sequence of records and frames produces the expected transcript byte-for-byte (the fixture is the transition list, not the printer's own output)
- [ ] 3.3 The document: `reviewDocumentPath(dataDir, reviewId)` = `<dataDir>/reviews/<reviewId>.json`; `buildReviewDocument(...)` from `review.load`, `session.rounds` (for `currentGenerationId`), one `board.read` per `LENS_KINDS` entry, the final lanes, the range and timings; written with the directory created and an existing file replaced; the path printed as the last stdout line. Controls: `--out` wins over the default; a lens that `board.read` reports absent lands as `absence` with no `board` key; the last stdout line is the path and nothing follows it
- [ ] 3.4 Reattach: `reattached: true` with a settled review at the requested head OID writes the document without minting (control: `session.mint` is invoked once and no preparation starts; elapsed under two seconds on the fixture); a running preparation is attached to; a moved head mints with `replacesSessionId` and prints the archived id (control: the old session's `archivedAt` is set and exactly one new session exists); a `failed` boards stage with a `reviewId` takes `session.retryPreparation`
- [ ] 3.5 Exit codes: `0` on settle; `1` with the document written and `outcome` set for `failed`, `cancelled` and timeout (control: a fixture whose boards stage fails yields exit 1, a document whose `outcome` is `failed` with the reason, and three settled lanes preserved); `1` with the daemon-absent message before anything else when `findHealthyDaemon` is not healthy; a timeout leaves the preparation running (control: the session's preparation is still `drafting` after the CLI has exited)
