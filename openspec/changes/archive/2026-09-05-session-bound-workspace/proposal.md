## Why

A lens seat receives ~110,000 characters of context JSON before it reads a line of the change, and the Design seat received 241,848, of which 103,000 were the bodies of 34 openspec proposals embedded so the seat could pick one (issue #785; the measured section of `docs/developing/concepts/t3code-sidecar.md`). Every one of those characters is billed to the user's subscription on every seat and every retry, the survey of 2026-09-03 found 24 prompt sites that carry context inline and 13 with no bound at all, and the machinery that produces the biggest payload, a 64-hex hunk-id inventory the seat must copy back so a coverage gate can count it, produced 239 violations on a 74-file branch that no reader will act on. Alongside that, Rennet runs its own worktree zoo (a detached worktree per round operation, a review evidence worktree, a per-PR worktree, plus the user's checkout) while the vendored T3 sidecar already binds a thread to one worktree and checkpoints every turn; Rennet creates every thread with `worktreePath: null` and uses none of it. Rai's rulings of 2026-09-03: never inline context, one branch or worktree per session the way T3 Code does it, and simplicity of the final result over simplicity of the diff.

## What Changes

- **One workspace per session, bound once.** A session binds to one branch or worktree at creation: a branch review binds to the user's checkout when it sits on that branch, otherwise to a worktree Rennet creates for the branch; a PR-snapshot review binds to a worktree at the PR head. Every child of the session runs there with that cwd: the six lens seats, the chat thread, the handoff thread, the round worker, and every cold utility turn (scout, repo map, delta digest, coverage, opener, PR body, refine, CI classification, finding verification). T3 threads are created with the bound `worktreePath`.
- **BREAKING: a round is a turn on the bound worktree.** The worker commits on the session's branch; T3's per-turn checkpoint refs are the receipt and the delta; the review advances to a new patchset captured from the bound worktree after the turn. Deleted: the per-operation detached worktree planner and `~/.rennet/round-worktrees`, the "land only the worker delta" collation landing, `settleRoundCommits` (`git add -A`), the review evidence worktree, the WSL round-worktree path translation, and the non-forcing worktree cleanup that refused on stray files.
- **Never inline context.** Anything a turn needs beyond its instructions is written as a file under the bound root's `.rennet/context/<sessionId>/` with a `README.md` index; the prompt names the path and the agent reads what it decides it needs with its own tools, exactly as it reads the checkout. The files are purged when the session is archived (T3's "settled"), from the archive hook that already deletes the session's threads, plus an orphan sweep at daemon start. Rennet's managed `.rennet/.gitignore` block gains `context/`. The 24 inline sites are converted or deleted, biggest first; each PR states the prompt's size before and after.
- **Citations by path and line; hunk ids leave the model contract.** A citation is a path plus a 1-based line range on the new or old side (the existing `codeRef` shape). Lint resolves a citation against the patchset on the daemon; an unresolvable citation stays a violation. No hunk inventory is written at all; the seat runs `git diff` itself. `skippedHunks` and the composition cross-lens coverage gate are removed; coverage, if the surface wants a mosaic, is a server-side projection from citations. Delta marks between generations key on path and span. A hunk id may survive only as an internal delta-packet key for the diff renderer.
- **BREAKING: the Design lens finds the spec itself.** The design-artifact bundle, its discovery, limits, the transport fit from #782, the `designArtifacts` schema and the no-material candidate accounting are deleted. The Design prompt tells the seat to find the spec for this branch if one exists (openspec changes, BMAD, Kiro, grill-me, ADRs, superpowers; `git log base..head` and the PR body are the clue) and draft the Design board from it. When no spec exists the Design lane settles absent: the bench reader says "no spec found for this branch", and the finished board views simply have no Design tab; no empty board is drafted.
- **Repairs stay pointer-only everywhere.** The ephemeral legs' `renderRetryPrompt`, which re-sent the base prompt and the whole failing board, is replaced by the pointer-only repair turn the T3 leg already uses.

## Capabilities

### New Capabilities
- `session-bound-workspace`: one branch or worktree per session; every child runs there with that cwd; a round is a turn on it with T3 checkpoints as the receipt; the worktree zoo is gone.
- `session-context-files`: the no-inline-context rule as behaviour: `.rennet/context/<sessionId>/` written by one writer, indexed by `README.md`, referenced by path in prompts, ignored by Rennet's managed ignore block, purged on archive and swept at daemon start.
- `path-line-citations`: citations are path plus line range; the daemon resolves them against the patchset; hunk ids, the inventory, `skippedHunks` and the coverage gate leave the model contract.

### Modified Capabilities
- `lens-board-drafting`: the Design lens drafts from the spec it finds in the checkout, has no artifact bundle, and is absent when no spec exists; drafts cite by path and line; the repair contract is pointer-only on every leg.
- `round-regeneration-reveal`: "cross-lens coverage is honest without becoming a reveal barrier" becomes a server-side projection with no seat-side skip accounting; an absent Design lane is a legitimate settled state of the reveal.
- `round-harness-dispatch`: the round worker runs in the session's bound worktree and its provenance carries the T3 checkpoint ref, not a detached worktree path.
- `review-round-loop`: a round advances the review by committing on the bound branch; the patchset after a round is captured from the bound worktree.
- `handoff-bundle-composition`: the executable work order is referenced as the persisted file it already is, not embedded verbatim in the prompt; the run executes in the bound worktree.
- `angle-prompt-contract`: the context layer of an assembled prompt is a path reference, never a payload; no prompt site interpolates data beyond its instructions.
- `t3code-sidecar`: seat threads, the session thread and the handoff thread are created with the session's bound worktree, never the project root.
