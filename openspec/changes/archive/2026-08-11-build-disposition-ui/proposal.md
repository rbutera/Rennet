## Why

Issue #11 shipped the canvas rendering surface: the five canvases on screen, the zoom ladder, roll-up-by-default, the basic approve affordance, and the group-act fan-out (`fanOutApproval`). It deliberately stopped at the *user-sovereign authoring depth* — and named #17 as the owner of "the deep comment/question authoring UX (inline refinement, batch adjudication view, orphan tray)" (build-canvas-ui proposal, Impact). This change is that depth.

Rennet's core principle is "approve at ANY granularity … the whole point is to make the process smooth and quick" (Contracts §1; the voice Q&A, 2026-08-06). The half that makes it real for the reviewer is: author a disposition at *any* altitude of the zoom ladder; type a *messy, lazy* body and have that be the supported path; see *exactly* what will publish before it publishes and be able to withdraw with no residue; never lose a disposition silently when the patchset advances; and see the totality/residue of the review as a coverage surface (OQ4 closed — collapse is never read). This change adds those, extending #11's seam rather than duplicating its zoom/roll-up/read.

## What Changes

- Add **full-granularity disposition authoring** (`canvas/authoring.ts`, pure): `authorDisposition(canvas, act)` resolves an authoring act at every altitude of the zoom ladder — `line` / `hunk` / `symbol` / `element` / `cohort` / `rollup` — to the per-anchor L2 disposition writes it covers, and returns a **trace** binding the one user act to the several writes it produced. Roll-up / cohort / element reuse #11's `fanOutApproval`; hunk / line resolve through the L0 substrate; symbol is an element granularity carrying the symbol label. A group act is ONE user act fanning out to per-anchor L2 (never N clicks).
- Add **raw-draft capture + the batch view** (`canvas/authoring.ts`, pure): the disposition body is the user's raw, sovereign input — lazy / vague / half-formed is the SUPPORTED path (no validation, no refinement here). The batch is exactly what will publish (someone else's PR) or hand off (own branch): the L2 payload as a list, upsert-by-path (matching the engine's replace-by-path `DispositionSet`), with edit-body / edit-type / **withdraw-before-publish that leaves zero residue in the payload**. The rendered batch view is byte-identical to the published payload (asserted, not eyeballed). The `#19` refinement loop (refined / published forms + inline thread) is a documented seam on the draft; the raw body stays sovereign.
- Add the **three-state read fold** (`canvas/read-state.ts`, pure, event-sourced): read-state is defined by ACTIONS only — a disposition (`Actioned`) is `read`; a scrolled-through-but-never-actioned chunk is at most `skimmed`; a collapsed / never-seen chunk is `unread`. Precedence is max-rank so the fold is order-independent and **rebuilds identically from event replay**. Collapse can never mark anything read (OQ4). A **coverage mosaic** projects read / skimmed / unread over the whole changeset, with keyboard traversal to the next unread thing.
- Add the **orphaned-disposition surface** (`canvas/authoring.ts`, pure): `orphanedDispositions(before, after)` returns the dispositions present before a patchset activation and absent after — exactly those the engine's conservative byte-identical carry dropped. They surface in an **orphan tray**, visibly, never vanishing.
- Add the **components** (`components/`): `BatchView` (the publish/handoff payload with edit/withdraw), `OrphanTray` (dropped dispositions on patchset advance), `CoverageMosaicView` (read/skimmed/unread mosaic + next-unread), and `GranularityAuthor` (the disposition affordance at each altitude of the ladder). They are wired into `CanvasWorkspace` as ADDITIVE, optional sections (rendered only when their props are supplied), so #11's existing surface and tests are untouched.

## Capabilities

### New Capabilities

- `disposition-ui`: full-granularity disposition authoring with an act→writes trace, raw-draft capture and the batch view (edit / withdraw-with-zero-residue / byte-identical publish payload), the action-defined three-state read fold with a replayable coverage mosaic and next-unread traversal, and the orphaned-disposition tray on patchset advance.

## Impact

- Adds `packages/ui/src/canvas/authoring.ts`, `packages/ui/src/canvas/read-state.ts`, `packages/ui/src/components/batch-view.tsx`, `orphan-tray.tsx`, `coverage.tsx`, `granularity-author.tsx`; extends `packages/ui/src/components/workspace.tsx` (additive optional sections) and `packages/ui/src/index.ts` (new pure exports for the app + the #19 seam). No new package, no new runtime dependency (React + zustand already present), no dependency-arrow change: the `architecture` and `licenses` gates are untouched.
- `layer:ui` stays clean: the new logic consumes `Disposition` / `Canvas` from `@rennet/types` and `parseAnchor` from `@rennet/protocol`; it never imports `@rennet/core` and never runs the projector. Orphan computation is a set difference on the review's disposition lists across an activation, so it needs neither core-private carry logic nor patch text.
- Seam with #11 honoured: this slice EXTENDS `fanOutApproval` / `canvasCoverage` for the authoring depth; it does not re-implement zoom / roll-up / read. The #11 store's "holds NO read state" boundary is preserved — the three-state fold is a pure function over an event list, not ephemeral view state.
- Deferred: the comment-refinement authoring UX (#19: refined / published draft forms + the inline clarification thread) — the draft type leaves the seam; an interactive-DOM test env (#53) — the new logic is fully pure-tested and the components are SSR-string tested (the #11 pattern), so no DOM env is required.
