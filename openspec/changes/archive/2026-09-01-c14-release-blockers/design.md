# Design

## Context

See `proposal.md` — Why. Six open C14 issues plus folded-in #726, five subsystems, one journey. Constraints that shape the approach:

- **Baseline is `origin/main@1ccd3f14`, and two large pieces already landed there.** PR #692 landed Claude/Codex round resolution: `resolveCodingHarness` / `runResolvedCodingHarnessTurn` (`create-server.ts:438/535`), sticky per-session pin, typed unavailable failure, no cross-provider fallback, `harness` stamped on the round receipt and displayed in the greeting and ledger. PR #728 landed the verified-report-before-fanout handoff ("a required report is the one sequencing boundary"). This change targets the residue — both reviews confirmed the residue is real: the `Promise.allSettled` barrier plus coverage-gated announcement (`lens-pipeline.ts:1387`), no durable per-phase timings, no per-lane budgets, the unbounded classifier envelope (`lens-pipeline.ts:940-957`), the `.rennet/boards` capture contamination, and the #548/#549 lens defects (`lens-pipeline.ts:1251`).
- The #689 rework landed: the round report is one narrow verified classification turn and zero-element boards are no longer announced as arrivals. #725/#727 build on that boundary, they do not reopen it.
- The board service is authoritative and must stay that way (#548 acceptance): repairs happen producer-side, the service keeps rejecting.
- Dogfood measurements (2026-09-01): 60 top-level provider calls in the five-lens fan-out; a 12-call serial Codex chain spanned ~646 s of critical path; the barrier held every finished result until the slowest lane ended.
- Rule Zero: none of this work adds gates. Reveal policy, budgets, and typed failures are product honesty and speed, not ceremony.

## Goals / Non-Goals

**Goals:**

- Close #548, #549, #681, #725, #726, #727, #729 to their stated acceptance, under the C14 closing standard (launched-app proof + positive controls).
- One shared authority for "which paths are app-owned" consumed by capture, the watcher, freshness, and the board-store writer.
- Per-lane, per-generation telemetry durable enough that latency can never again hide under one label — and reveal state that survives restarts.

**Non-Goals:**

- Re-architecting the lens pipeline or the report gate beyond reveal/budget/validity policy.
- Bitbucket, Jira, Linear, or any post-C14 roadmap work.
- Release engineering: #298/#330 own signing, installers, and update verification. Closing C14 is necessary, not sufficient, for the public release.
- Classification receipts / provider-side idempotency (#727 names it optional follow-up).

## Decisions

**D1 — Repair refs only when provable; never drop-and-accept (#548).**
Add a ref-admission pass where lens output becomes a board write: every element reference is checked against the exact target document. An inadmissible reference is repaired only when its unique intended target is provable from the captured patchset, with a recorded account; otherwise the lane retries or settles as a typed failure. Dropping an element to make a board acceptable is forbidden — an accepted board that silently omits produced material contradicts the complete-coverage ruling and turns a producer defect into a quiet lie. Alternative — teaching the board service to accept-and-fix — rejected: it makes the authority lenient and hides producer defects. The production `bad-ref` shape becomes a regression fixture; a positive control bypasses repair and asserts service rejection.

**D2 — Extend the canonical settlement domain; do not invent a parallel one (#549).**
The durable model already distinguishes `lensBoards` / `absentLenses` / `failedLenses` with typed absence reasons (`no-material`, `no-decisions`, `no-findings`, `no-noise` — protocol `session/model.ts:126-133`). The #549 gap is narrow: the "initial drafting turn did not emit a board" path settles terminal at `lens-pipeline.ts:1251` instead of retryable, and the `no-noise` absence needs first-class success presentation. The work extends `LensBoardOutcome` and its consumers — retryable classification for no-board, lens-specific admissible absences (Sequence admits none) — rather than wrapping seats in a new union. A second settlement model would be a second lens lifecycle system.

**D3 — #681 is landed; the residue is proof, provenance edges, and docs.**
PR #692 already implements resolution, pinning, typed unavailability, and durable displayed provenance. Remaining work: (1) the launched-app second-round proof in both single-harness cases with a positive control for missing/misresolved harnesses — #681's acceptance explicitly requires it and it has never run; (2) the coverage seat (`runLiveCoverage`, still Claude-hardcoded around `create-server.ts:2204`) gets honest provenance or typed absence when Claude is not the resolved harness, so a Codex-only install's coverage state is truthful; (3) verify `docs/using/guides/install-a-coding-harness.md` claims against landed behavior. Alternative — re-implementing dispatch resolution per the original issue text — rejected: that code exists; re-doing it is the stale-worktree failure mode CLAUDE.md warns about.

**D4 — Per-lane settle events replace the barrier for every generation, with durable reveal state (#725).**
The barrier and coverage-gated announcement affect the initial generation and post-round regeneration alike — both go through the same pipeline, so the fix applies to both. Core lanes (Sequence, Decisions, Flagged) start when their inputs are ready (initial: captured patchset; post-round: the verified report #728 already sequences) and each lane publishes its settlement the moment it lands. Coverage becomes a generation-keyed durable state (`pending`/`complete`/`failed`) the client renders explicitly — note `compose.ts:79` returns violations without amending boards, so coverage annotates and flags, it never rewrites a revealed board. Per-lane settlements are durable and keyed to the generation attempt; writes from superseded attempts are rejected, and reconnect/restart reconstructs the partial state. `Promise.allSettled` may remain for run-completion bookkeeping, never for reveal. Timing: one durable record per phase (report, per-lane draft/repair/post-process, coverage, reveal, time-to-first-core-board), one draft record PER SEAT so a dual lane names both harnesses and D8 can derive run mode from stages, and time-to-first-core-board measured from the caller's own wait origin. Retry budgets become a per-lane, per-attempt table; a repeat whole-board attempt draws the table's repeat entry — bounded at no more than the first attempt's, and never zero, since a zero repeat terminates a lane the restart recovery exists to re-draft. **Working latency targets (stated assumption, Rai adjustable): on the tiny-round proof, first core board ≤ 2 minutes from round land, full settle ≤ 5 minutes.** Timings alone cannot pass the proof; the targets can fail it.

**D5 — Classifier envelope is a locally-enforced contract with named limits and transport-level caps (#727 + #726).**
A manifest builder produces canonically ordered evidence (path-then-position ordering) with stable ids; a single serializer measures UTF-8 bytes against limits declared as named constants in one protocol-level module (the contract doc carries the same numbers) and fails typed — zero provider calls — on overflow. Evidence is a discriminated union (`text-hunk | binary | mode-change | rename | …`); no variant invents a line anchor. Output side: the session-spec contract gains an output cap the Claude and Codex adapters both enforce at the transport boundary — raw-size rejection before structured-output decoding — because core only ever sees decoded values; decoded entry/cardinality caps then apply before persistence. The decoded classification must partition manifest evidence ids exactly once (every id in exactly one ask or the `beyond asks` bucket; unknown/missing/duplicate rejected) — #726 folded in while the manifest is being built, when it costs a validation pass rather than a retrofit. Cap failures route to the durable round-failure path and never spawn another turn.

**D6 — Sanitize the reviewed tree, then derive everything from it; one authority owns app-owned paths end to end (#729).**
Capture currently derives the reviewed-tree OID, diff, and patchset identity from the complete tree (`git-capture.ts:189/269`), so filtering only file lists and raw diffs would still leave a contaminated `reviewedTreeOid` changing identity. Instead: exclude app-owned paths from the temporary reviewed tree itself, then derive OID, diff, files, byte counts, intent, and identity from that one sanitized tree. The app-owned prefix (`.rennet/boards/`) lives in one shared module consumed by `git-capture`, `repo-watcher`, freshness evaluation, and the board-store writer (`boards-runtime.ts:29`) — the writer consuming the same constant means the storage root can never silently move out from under the exclusion. Tracked content elsewhere under `.rennet` still captures (tracked = intentional), and the watcher's blanket `.rennet` ignore narrows to the app-owned prefix with a positive control proving a tracked `.rennet/` project-file edit still invalidates. Fixture shapes: `.rennet/boards-extra` (prefix boundary), separator variants, staged and untracked board artifacts. Alternatives — excluding all of `.rennet` (forbidden by acceptance) and writing an ignore rule into the user's repo (Rennet never stages or commits user project context) — both rejected.

**D7 — The round loop is unbounded by construction; the fix is a sweep, not a mechanism (Rai, 2026-09-01).**
Recon found no numeric cap: `dispatch/round.ts` handles repeat dispatch ("run again" semantics, ~line 296), and rounds-UI lanes are lens lanes, not round slots. The "two rounds" impression came from proof scope (#685) leaking into framing. So the work is contractual: the `review-round-loop` spec states the unbounded loop with its real preconditions — dispatch needs the reviewer's own current-branch review and at least one staged ask; teammate/retrospective reviews correctly refuse; a PR **draft** does not terminate the loop, only submit does. Implementation sweeps prompts, UI copy, and fixtures for ordinal *assumptions* (a cap, a round-two special case) while leaving legitimate descriptive names alone. Proof: a parameterized arbitrary-N state-machine test plus one launched three-round journey — three rounds only disproves a cap of two; the N-machine disproves the class. Alternative — a round-count config — rejected: there is nothing to configure; a cap is the bug, not a feature.

**D8 — Benchmarks ride the #725 timing spine; one recorder, three consumers, per-stage truth.**
One versioned benchmark record schema sits on the durable per-phase timing records D4 requires: deterministic Repo Map build stages (per stage; the context-map kill removed the model-backed layers), lens lanes (draft, dual review, repair, post-process, per-lens total, whole process), and the report gate. Every stage record carries the harness and model that actually executed it — Model Council routes per job, so run-level labels (dual-model / Claude-only / Codex-only) are derived from stages, never assumed from settings. Failed and aborted runs record as such rather than vanishing. Recording is controlled by a default-on `client-settings.json` setting surfaced as a Settings toggle. Consumers: (1) the Settings benchmarks panel, reading durable records over a served command, virtualized so a long history stays smooth; (2) a deterministic developer-run export command that aggregates records into committed JSON under `docs/` with provenance (date, machine, revision) — Rai runs it against his own dogfood data and reviews what he commits; (3) the docs benchmarks page rendering that data, failing the build on missing/corrupt data. Alternatives — a separate metrics store (two timing systems drift) and hand-written docs numbers (they rot into marketing) — rejected.

## Risks / Trade-offs

- [Progressive reveal shows a board that coverage later flags] → coverage is an explicit visible generation state; `compose.ts` coverage reports violations without amending boards, so a revealed board never mutates — the coverage state updates beside it.
- [Ref repair could silently rewrite meaning] → repair only on provable unique targets, every repair recorded in the lane account; unrepairable means typed failure, not omission; the positive control keeps the service-side rejection alive.
- [Codex and Claude rounds diverge behaviorally] → both harness cases run the same launched-app second-round proof; per-stage provenance makes any divergence attributable.
- [Latency targets chosen wrong] → they are stated design assumptions, cheap for Rai to adjust; the alternative (timings with no threshold) lets an 11-minute run pass the proof, which is how we got here.
- [Byte/entry limits chosen wrong] → named constants in one module, documented in the classifier contract doc; overflow is a typed recoverable failure rather than truncation, so a wrong limit is visible and cheap to change.
- [Capture exclusion misses a future app-owned path] → single shared authority module consumed by writer and readers alike; adding a path is one edit.
- [Ordinal-assumption sweep misses a buried "round two" special case] → the arbitrary-N machine test contains the shape; any surviving cap fails it.
- [Default-on recording adds overhead to the hot path] → records are written at phase boundaries already instrumented for #725; the toggle exists for the day measurement itself measurably costs.
- [Committed benchmark data goes stale as the product speeds up] → the docs page states provenance (date, machine, revision); stale-but-labeled beats fresh-but-invented, and re-export is one command.

## Migration Plan

No data migration. Existing durable sessions and patchsets stay valid; new timing records, reveal-state records, and provenance fields are additive, and the benchmark schema is versioned from day one. Repositories that already ignore `.rennet/` see no behavior change from D6. Rollback is reverting the PRs; no persisted format changes shape.
