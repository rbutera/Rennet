# C7 — Chat: the persistent dock, transcript, and composer (#489)

## Why

INVENTORY §5 carries 34 `[ws:C7]` claims describing the chat dock — the one surface the reviewer talks to the orchestrator through, present on every review-session screen and holding its conversation across navigation. It is where a live turn narrates itself (thought blocks, action steps, streaming prose), where staged comments and quotes ride into the composer as badges, and where compaction is shown honestly instead of hidden. None of it exists in `app-ui` yet: C3 landed the dock's SLOT — an always-mounted, width-0-when-closed, `inert` `<div data-slot="chat-dock">` outside the outlet (`routes/layout.tsx`), explicitly "C7 fills the dock's internals" — and C4 landed the shared `review/code-block.tsx` a transcript turn renders code through, plus the `review` slice's `codeComments`/`quoteThreads` the composer badges read. The dock component itself is still spike-only, and the spike drives its transcript from a scripted fixture (`useState<TurnData[]>` seeded from `lib/conversation-data.ts`, a 700 ms `setTimeout` faking the orchestrator's reply) behind the `useCodeComments()` shim. C5 (board), C6 (diff), C8 (exits), C9 (rounds) all render beside this dock; the reviewer expects the same conversation to survive moving between them. C7 ports the PRESENTATION (JSX, layout, streaming animation, composer mechanics) and rewrites the STATE onto the data seam: historical turns from the session-transcript projection, live turns folded from `onAskStream` via `useCommandStream`, sends via `review.ask` through `useMutation`, badges from the real `review` slice.

## What Changes

All in `packages/app-ui/src/chat/` (new), plus one minimal edit to `routes/layout.tsx` to mount the dock INTO C3's existing slot. On C1's data seam (`useCommand`/`useMutation`/`useCommandStream` in `data/`), the `review` slice (`store/review.ts`, read-only here — C4 already extended it), and C4's `review/` barrel (`CodeBlock`, `ReferenceChip`). **Zero new dependencies**: `lucide-react` and the streaming-word CSS animation are already `app-ui` assets. The #251 conversation-durability commands (`review.ask`, `review.reattach`, `onAskStream`) are already dispatch-bound in `packages/server/src/dispatch.ts` and their stream schema (`reviewAskStreamEventSchema`: `ask-focus`/`ask-delta`/`ask-complete`/`ask-interrupted`) lives in `protocol/wire.ts`; `MemoryBridge` already exposes `onAskStream`/`emitAskStream`, so the stream fold is proven now.

- **`chat/chat-data.ts` — the single data-resolution point (mirrors `shell/sidebar-data.ts` and `review/citations.ts`).** The dock takes no transcript props; every turn it renders, every stream it folds, and every send resolve HERE, two lifetimes in one file:
  - **Live now (dispatch-bound #251):** the reviewer's ask travels as `review.ask` via `useMutation`; the live turn's tokens fold from `onAskStream` into the read via `useCommandStream({ channel: "askStream", subscriptionKey: reviewId })`, reducing `ask-delta`/`ask-complete`/`ask-interrupted` into the streaming turn (the reducer honours the monotonic `seq`, rejecting a replayed delta, matching the wire contract); `review.reattach` reloads persisted ask-threads + resumes in-flight turns after a reload. Tests drive this through `MemoryBridge.emitAskStream`.
  - **B9-gated (stubbed):** the full historical SESSION transcript — the orchestrator's coding turns (thought blocks, action steps, prose), the `compact_boundary` rows, and the harness-reported context figure — is B9's projection (#466: the harness CLI owns transcript/compaction). Protocol carries no `session.transcript` read yet, exactly as it carried no `session.*` for the sidebar. Until B9 lands, the LIVE client shows an honest empty transcript (no invented turns), and tests supply the transcript through a `SessionTranscriptProjection` context — the spike's scripted reply pairs return here as MemoryBridge stream fixtures + projection fixtures. When B9 lands, the projection read becomes `useCommand("session.transcript", …)` and the context is deleted — **this is the only file that changes**.
- **`chat/chat-dock.tsx` — the dock, mounted ONCE.** Ported from the spike's `ChatColumn`, rendered as the child of C3's `data-slot="chat-dock"` in `routes/layout.tsx` (its non-unmounting lifetime, already built for R47/R52, IS the transcript-identity guarantee). Three stacked regions inside the slot: header, transcript, composer. Reads `chat-data.ts`, never a fixture module.
- **`chat/chat-header.tsx` — the one dock header.** Ported from the spike's `ChatHeader`: the session trail (reusing `shell/trail.tsx`, C3-landed) + the collapse control (writes `uiActions.setChatOpen`, the C3 `ui`-slice flag the slot already reads). No bespoke bar.
- **`chat/conversation-pane.tsx` + `chat/turn.tsx` — the transcript.** Ported from the spike. `ConversationPane` is the scroll region with bottom-anchored auto-scroll on append; `Turn` renders a user bubble or an orchestrator turn (lead prose, activity preface, body of prose/code blocks). The record-vs-arrival distinction (`animate`) is kept: historical turns replay instantly, only turns arriving live word-fade in. Code blocks render through C4's `review/code-block.tsx` (reconciliation 4), not the spike's local one.
- **`chat/thought-block.tsx`, `chat/action-step.tsx`, `chat/streaming-prose.tsx` — the live-narration sub-blocks.** Ported. `StreamingProse` (per-word CSS-delay reveal) and the collapsing `ThoughtBlock` ("Thinking" → "Thought for Ns", manual re-expand) and `ActionStep` (running spinner → done label). The spike's self-timed `setTimeout` reveal (a fixture animating itself) is rewritten to reflect the turn's real streaming STATE (`streaming`/`complete`/`interrupted` from the stream), so a block's live/settled look follows the data, not a timer (reconciliation 2).
- **`chat/composer.tsx` — the input bar + badges.** Ported from the spike's `InputBar`. Textarea (auto-grow, Enter-sends / Shift-Enter-newline, IME-safe), send button, image-paste badges. Composer badges read the real `review` slice (reconciliation 5): comment badges from `review.codeComments`, quote badges from `review.quoteThreads`; removal calls `reviewActions.clearCodeComment`/`removeQuoteComment`. Send fires `review.ask` via `chat-data.ts`'s mutation. Orchestrator-presence affordance (the model dot / "working" state) reflects whether a turn is in flight.
- **`chat/anchored-thread.tsx` — anchored-thread content, transcript-side (#466).** Renders a `review.quoteThreads` thread's messages inside the transcript when a board ref points at it (reconciliation 6). The board (C5) holds the anchor→thread ref and the marker; C7 owns only the CONTENT side.
- **`chat/compaction-row.tsx` — compaction, honest.** A `compact_boundary` timeline row in the transcript and the ask-don't-estimate context meter (reconciliation 7). Rennet never ESTIMATES a token budget: the meter shows the harness-reported figure or says it doesn't know. Data is B9's (stubbed via the projection today); the honest rendering is C7's.
- **`chat/index.ts`** barrels the public surface (`ChatDock` and the seam types) for the layout to mount; `app-ui/src/index.ts` re-exports it.
