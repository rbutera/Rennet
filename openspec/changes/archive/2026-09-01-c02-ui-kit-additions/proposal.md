# C2 — UI kit additions: six generic primitives (#489)

## Why

Track C's surface rebuilds (C3–C13) compose from `packages/ui`, and the kit is six primitives short. The client asset (§1, [#489 comment](https://github.com/rbutera/rennet/issues/489#issuecomment-5431046569)) names them: `context-menu` (right-click on project/session rows), `collapse` (the grid-rows/`inert` primitive behind every fold — R47, autopsy keep-list), `resizable` (pointer-capture divider), `toggle-group` (segmented controls: verdict, scheme, sort), `kbd`, `progress`. Two are spike code ported under the 11-rule fence ([#489 comment 5431046732](https://github.com/rbutera/rennet/issues/489#issuecomment-5431046732) §3); four come from the shadcn/Base UI registry per the port arc (Base UI, not Radix). Autopsy S6 is the cautionary tale this change closes: the spike grew five hand-rolled implementations of "pick one of N" while its `ui/toggle-group` sat unused — so C2 ships the primitive AND the lint that forbids hand-rolling it again.

## What Changes

Six flat files in `packages/ui/src/components/`, barrel-exported from `src/index.ts`, kit conventions throughout (relative `cn` import, `data-slot` attributes, theme tokens only — the hex lint already covers `packages/ui`). Zero Rennet vocabulary, zero protocol types, **zero new dependencies**: `@base-ui/react@1.7.0` is already the kit's dependency and ships `context-menu`, `toggle-group` (+ `toggle`), and `progress`; `kbd` is styled HTML with no primitive underneath.

- **Registry four** — `context-menu.tsx`, `toggle-group.tsx` (with `toggle.tsx` if the registry item factors it out), `kbd.tsx`, `progress.tsx`, sourced from the shadcn/Base UI registry and adapted to the kit's existing shape (`dropdown-menu.tsx` is the sibling model for context-menu — same Base UI menu anatomy). "No selection" is modeled as `null`/empty, never `""` (S6).
- **Ported two, through the fence** — `collapse.tsx` from `spikes/board-prototype/components/collapse.tsx` (verified: exactly 35 lines, grid-rows `0fr→1fr` transition, content stays mounted, `inert` removes the closed state from the tab order — ported behavior-identical), and `resizable.tsx` from `spikes/board-prototype/components/resize-handle.tsx` (verified: 64 lines, pointer-capture drag, `role="separator"`, double-click reset — generalized per reconciliation 3).
- **Kit-not-hand-rolled lint (S6), armed** — a `no-restricted-syntax` selector over `packages/app-ui/src` banning hand-rolled toggle markup (`aria-pressed` / `role="radiogroup"` written directly in surface JSX), following the same checked-suppressions-baseline strangler pattern C01 established for the `.invoke` ban (reconciliation 2). Positive control mirrored as a lint test, same pattern as `hex-lint.test.ts`.
- **Test mounts** — every one of the six gets a test mount in the kit's house test-mount convention (`@vitest-environment happy-dom` + testing-library, per `smoke.test.tsx`), including the packet's named proof: `collapse` keeps content mounted and tab-order inert when closed.

## Reconciliations against main (packet drift, recorded per the dispatch rule)

1. **"Story/test mount" resolves to test mounts.** The repo has no story infrastructure (no Storybook, no preview app for the kit); the kit's mount convention is testing-library smoke tests (`packages/ui/src/components/smoke.test.tsx`). Introducing a story subsystem would be a new dependency the packet does not ask for — each primitive gets a test mount instead, which is the convention the verification sentence can actually bind to.
2. **The S6 lint needs a quarantine, and a lintable proxy.** Five incumbent `app-ui` files hand-roll `aria-pressed` segmented controls at HEAD (`symbol-inspector.tsx`, `source-switcher.tsx`, `front-door.tsx`, `project-detail.tsx`, `settings-screen.tsx` — 3 sites). Arming the lint naively reds the gate, so it follows C01's established mechanism: the selector is added to the app-ui surface block in `eslint.config.mjs` (re-listing the block's existing selectors — flat config replaces, never merges) and the existing sites are captured in the `eslint-suppressions.json` checked baseline, so a NEW hand-roll fails while each surface rebuild drains its sites and C14 verifies the baseline empty. Also: a lint rule cannot recognise "segmented control" semantically — the enforceable proxy is the accessibility markup a hand-roll must carry (`aria-pressed`, `role="radiogroup"`); `packages/ui` itself and test files are exempt, since the kit is where that markup legitimately lives.
3. **`resizable` is generalized in the port; the spike component is chat-furniture.** `resize-handle.tsx` hard-codes Rennet vocabulary a kit primitive cannot carry: `MIN_CHAT_WIDTH`/`MIN_SURFACE_WIDTH`/`DEFAULT_CHAT_WIDTH` constants, `aria-label="Resize chat column"`, and a max-width derivation from `window.innerWidth`. The port parameterizes: `value`/`onChange`/`min`/`max` (or a max-derivation callback)/`defaultValue` (double-click reset)/`aria-label` become props; the chat-specific numbers move to the consumer when C3 wires the shell. This also repairs autopsy S1 at the source — the spike's store imported `DEFAULT_CHAT_WIDTH` *from the component*; the kit primitive owns no domain constant for anything to invert onto. Vertical (column) orientation only, matching the one consumer shape that exists; an orientation axis is added when a consumer needs it, not before.
4. **Fence rule 5 is a no-op for these two ports.** Verified: neither `collapse.tsx` nor `resize-handle.tsx` surfaces any `text-[Npx]` bracket, so there is no typography gap to fill in `packages/theme` in this change. The resize handle's `w-[6px]`/`-mx-[3px]` are hit-area physical sizes, not typography — they stay.
5. **Packet-vs-reality: clean.** Both spike files exist at the stated shapes (collapse is exactly the 35-line grid-rows + `inert` disclosure the packet describes). Base UI is installed at the pinned kit version and its component set covers every registry-sourced primitive that needs one; no registry name mismatch found.
