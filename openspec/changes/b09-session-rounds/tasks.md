## Cluster 5 — row-click mints session & claims target; re-entry reattach; pipeline idempotent (clause: row click / re-entry / idempotency / staging one-path)

- [ ] 5.1 A New-chat row resolving to a branch/PR **mints a session and claims the target in one act** — the dispatch handler (`server/dispatch/`, `session`/`review` family) creates the `SessionModel`, sets its `Claim` (branch + PR as ONE claimed thing per `ClaimSchema`), and every New-chat row resolving to that branch or PR **disappears while the claim holds** (claim-dedup on resolve). A merged target keeps its claim; archive is the only release (cluster 1 semantics).
- [ ] 5.2 **Re-entry mid-generation reattaches**: entering a row whose session is already live (a generation in flight) **reattaches** to that session — it does not mint a second. The drafting **pipeline starts idempotently per session**: a guard keyed on the session (+ patchset generation) ensures a second entry never double-starts `runLensPipeline`. Route session/round board mutations through the existing event-log→projection path (reconciliation 4) — no parallel writer.
- [ ] 5.3 Tests: a row-click mints a session with the branch+PR claim and hides sibling New-chat rows for the same target; a second click mid-generation reattaches (same session id, no second pipeline start — the idempotency guard is exercised, a positive control that fails if removed); a merged target keeps its claim; writes land through the sanctioned client only.
