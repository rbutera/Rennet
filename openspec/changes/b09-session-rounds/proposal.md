## What this change does

Builds the **runtime** for the durable session and the rounds loop over the shapes B03 froze in `packages/protocol/src/session/model.ts` (#466, header: *"Shapes only: the state machine, locks, and rework queue are B9's"*). No protocol edit; every shape is consumed, never re-modeled. This is where B08's `runLensPipeline` finally gets a caller.

- **Session = first-class durable root** (#466 res. 1–2). A new session runtime owns the harness cursor, the threads, and the claim (`SessionModel`). A review attaches `1:0..1` by `reviewId` (referenced, not absorbed); a no-target session has no claim and **upgrades in place** when a target binds; the claim **locks once boards exist** (a generation has been minted) — a new target then requires a **new session**. Archive is the only release (v1 soft delete via `archivedAt`). A file-backed `SessionStore` (adapters, following the `file-thread-store`/`file-project-store` precedent) persists it.
- **Harness = cursor-resume** (#466 res. 3, the T3 pattern). Interactive turns run **fresh-process-per-turn + SDK `resume`**: the CLI owns the transcript, compaction, and prompt cache; Rennet persists only the `HarnessCursor` pointer into it and re-passes it each turn. This adds the resume path the port left "absent by design" (reconciliation 2). Rennet owns the turn loop: **serialize turns per harness id** (one in flight at a time), **re-pass options every turn**, and a **resume-vanished fallback** — when the harness transcript is gone, rebuild context honestly ("context rebuilt") while the **boards stay canonical**.
- **Compaction surfaced honestly** (#466 res. 3 ripple). The harness's own compaction is shown, never hidden and never estimated: a **`compact_boundary` row** in the turn stream, a **PostCompact summary** surfaced to the reader, and an **ask-don't-estimate meter** (report what the harness says about its context, do not fabricate a token budget). Honest copy, not a gate.
- **Anchored threads** (#466 res. 7). Thread **content lives only in the session transcript**; boards and the diff hold **anchor→thread references** (`SessionThread` + `ThreadAnchor`). One mechanism carries code-line comments, prose-quote comments, and Explain; an `Ask` rides on the anchored arm when one is minted.
- **Staging writes, one path** (#466 res.). Session and round mutations that touch boards go **tool call → event log → projection** through the existing B04 choke point (`boards-runtime` → `projection` → `whiteboard-client`) — B09 routes through it, never a second writer (reconciliation 4).
- **Row click mints session AND claims target; re-entry reattaches; pipeline idempotent per session.** A New-chat row resolving to a branch/PR mints a session and claims the target in one act (`Claim` = branch + PR as one thing); re-entering mid-generation **reattaches** to the live session rather than starting a second; the drafting pipeline **starts idempotently per session** (a second entry never double-starts it).
- **Rework = one-shot workers outside the chat, serialized per document** (#466 res.). Rework runs as one-shot workers (not the interactive session), **serialized per document** so two edits to one board never race.
- **Rounds loop state machine** (#486 / R34, R57–R58). A round: **serialize dispatches**, run **watched live**, and record a `RoundRecord` pinning the asks dispatched, the worker commit range, the minted patchset generation, and the report board. Wire `runLensPipeline` as the consuming turn — the **round-report drafts FIRST** and gates the regeneration (R58), per-board **arrival events** drive the progressive reveal, and each board's coverage/blemish metadata is persisted through `persistBoardMeta` (reconciliation 5). The rounds ledger is data (`RoundRecord[]`), not UI (C9 out of scope).

## Out of scope

Chat UI (C7), rounds UI (C9), exits **composition** (B11 — B09 pins only the exit-lane ids its own dispatch loop routes on, per `AskSchema.exitLane`'s open string; B11 composes the exits). `SessionModelSchema`, `HarnessCursorSchema`, `ClaimSchema`, `ThreadAnchorSchema`, `AskSchema`, `SessionThreadSchema`, `GenerationSchema`, `RoundRecordSchema` are B03-frozen contracts — consumed, never re-modeled. B08's pipeline pure logic (`core/board/*`, `server/runtime/lens-pipeline.ts`) is consumed, never edited.

No frozen-shape edit; the generation id is an opaque string the guard never persists.

## Fix-loop amendments (PR #531 dual review — Codex + Opus)

**F2. Cursor persistence reloads the latest record — the turn loop can no longer lose a concurrent whole-record write (critical, cluster 2).** The turn loop captured the session at load, ran the async harness turn, then persisted `advanceCursor(pre-turn-snapshot, outcome)` — a whole-record overwrite. `SessionStore.addThread`/`archive` are NOT routed through the per-session turn serializer; they write the whole record directly. So a thread added (or an archive stamped) WHILE a turn was in flight was silently erased when the turn saved its stale snapshot (thread lost, archived session resurrected). Fix: after the turn resolves, RELOAD the latest record from the store and apply a cursor-only update to it (`advanceCursor(store.load(id) ?? current, outcome)`), on both the normal completed path and the resume-vanished fresh-turn path. Reload → advance → save runs synchronously (no `await` between), so no other store write interleaves the read-modify-write. The serializer stays the turn-vs-turn guard; this reload closes the turn-vs-direct-write window the serializer never covered. Proven: a thread and an archive that land mid-turn both survive the cursor persist (`turn-loop.test.ts`).
