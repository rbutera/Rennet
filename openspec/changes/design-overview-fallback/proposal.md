## Why

Most branches have no specification. The Design lens looks for one in the formats Rennet parses — an OpenSpec change, Kiro, BMAD, superpowers, an ADR, a grill-me `CONTEXT.md` — first on the host from the change's own paths and then, when the host located nothing, with a model seat that reads the commit messages and the pull request body and walks the places specifications live. When neither finds one, the lane settles `no-spec` and the Design tab reads "No spec found for this branch." That is an honest result. It is also the most common one, and on the drive fixtures it is what a reviewer sees on every branch that was written from a PR description and a couple of issues rather than from a spec directory.

The material the Design board exists to show — *what was this change supposed to do, according to its author* — is usually there. The PR description already sits in the seat's context directory as `pr.md`. Documentation the branch adds or rewrites is in the change index and the checkout. The issues the branch closes are fetched on review open by related-context retrieval and stored in the dossier, where nothing on the board path reads them. The seat is told the pull request body is its strongest clue to a specification, reads it, finds it names no spec, and settles absent with the intent it just read still in its hand.

So: when there is no deterministic or otherwise supported specification for the branch, the Design seat drafts a **design overview** from the PR description, the documentation the branch adds or changes, and the related issues from the project's configured tracker. The overview is what the author and the tracker say the change is for, rendered as a Design board that says what it is and where every line came from. `no-spec` remains the settlement for a branch that has none of the three either.

## What Changes

- **The Design seat drafts an overview instead of settling absent, when it has material.** After the seat has looked for a specification and found none, it checks three sources in order — the reviewed pull request's title and description, documentation files the branch adds or modifies, and the related issues the host retrieved — and drafts a Design board from whichever exist. It calls `settle_absent` only when all three are empty, and its note says so.
- **Related issues reach the Design seat as a context file.** The host writes `related-context.md` under the session's context directory from the dossier that related-context retrieval already stores for this review target and patchset: one region per tracker item with its id, tracker, title, state, URL, provenance and bounded body, and acceptance criteria when the tracker carries them. It is named in the Design prompt alone, beside `pr.md`, and never inlined. On the model-seat path with no host-located specification, the Design lane waits for the retrieval kicked at review open, bounded by a declared ceiling; past the ceiling the file carries the deterministically extracted refs with their URLs and says retrieval had not finished.
- **The overview says what it is.** Its document stats carry `Format: Overview` and `Specification: none found`; its intro's first sentence names the sources it was drafted from; every section's `sources` names the file it was read from; a decision the PR description or a document states carries `inferred: false` and its exact source, and the seat still draws no decision from code. An issue's acceptance criteria are `requirement` elements whose `shall` is the tracker's own text and whose `source` is the related-context file and the item id. The board carries no capability, requirement or task counts it did not read from a specification.
- **The overview is model-drafted only.** No host assembler renders a PR body: the deterministic Design fast path stays for specifications in formats the assembler renders, and a PR body is prose, not a document with obligations.
- **The residual absence keeps its words.** A branch with no specification, no PR paper, no documentation change and no related issue still settles `no-spec`, the bench reader still says "No spec found for this branch.", and the tab stays.

## Capabilities

### Modified Capabilities

- `lens-board-drafting`: the Design lens's absence requirement gains the overview arm: the seat drafts from the PR description, branch documentation and related issues when no specification exists, and settles `no-spec` only when none of the three exists.
- `session-context-files`: `related-context.md` joins the Design-only context files, written from the stored dossier, bounded, and honest about a retrieval that had not finished.

## Impact

- `packages/prompts/src/prompts/design.md`: the "When there is no specification" section becomes "When there is no specification: draft an overview", with the three sources, their order, the document shape and the residual `settle_absent`. `index.test.ts` gains the assertions.
- `packages/core/src/board/related-context-file.ts` (new): the context file builder, with a declared per-item and whole-file byte bound and a truncation line.
- `packages/server/src/create-server.ts`: the retrieval kicked at `onReviewOpened` is held per review so the lens pipeline can await it; `runtime/lens-pipeline.ts` gains `relatedContext` on its deps, the bounded wait on the Design lane's model-seat path when `designSources` is undefined, and the file in `designOnlyFiles`.
- `packages/adapters/src/live-review-backend.ts`: `runRelatedContextRetrieval` resolves with the dossier items it saved or loaded, instead of `void`.
- Docs: `docs/developing/concepts/lens-pipeline.md` (The Design lens), `docs/using/guides/getting-started.md` (the Design paragraph), `docs/using/concepts/common-questions.md` and `docs/using/index.md` where they list what the Design board reads, `docs/developing/concepts/t3code-sidecar.md` where it lists the seat context files.
- Harness cost: **this change grows what a Design session sends.** The Design prompt gains one section of roughly 1.6 kB. The context directory gains one file, unbilled until read, whose bodies are the dossier's already-bounded items (16 KiB each, 64 KiB whole). A branch that used to settle `no-spec` after a search now also drafts a board, so its Design turn is as long as a Design turn on a small specification instead of a search that ends in one `settle_absent` call. The bounded wait for retrieval adds wall-clock, never tokens, and only on the path that had no host-located specification.
- Issues: none open. The `no-spec` drive fixtures in the sidecar concept page (`drive/no-spec`, `nospec-big`) become the overview fixtures once one carries a PR body or an issue ref.
