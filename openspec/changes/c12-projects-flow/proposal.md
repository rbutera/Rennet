# C12 — Projects flow: add-project through first review (#489)

## Why

INVENTORY §10 is the largest client section — 111 `[ws:C12]` claims covering the whole add-project journey: the Add Project dialog and its inline directory browser, the Add Environment pairing dialog, the scout phase that precedes context-map generation, the prefilled provenance questionnaire, map generation with live progress and exits, the standalone context-map view, the ready state ending in a full-width **Start a Review** CTA, the New Chat target picker with its smart list, and `/archived`. C3 landed the shell and the router app is now the running client, but every one of these surfaces routes to a C1 interim screen. C3's reconciliation-4(a) named the debt explicitly: the WSL/source-aware add-project flow "has no router-side counterpart until C12 (projects-flow) rebuilds that flow." C12 rebuilds it, on the seams C1 shipped, reusing the presentation layers already vendored into `app-ui` (`components/directory-browser.tsx`, `context-map/model.ts`, `project/smart-list.ts`) rather than porting the spike's copies.

## What Changes

All in `packages/app-ui`, on C1's data seam (`useCommand`/`useCommandStream`/`useMutation`), the router routes C1 already declared (`newChat`, `archived`, `projectIndexing`, `projectMap`, `projectSettings` — all in `routes/url.ts` with builders), C3's shell (dialogs dispatch via `ui.openDialog`), and C2's primitives. **Zero new dependencies.** Surfaces build against `MemoryBridge` fixtures first; the one flow that genuinely needs unlanded protocol (session minting, B9) is quarantined to a final cluster (see reconciliation 3).

- **Add Project dialog** (`ui.openDialog("add-project")` from C3's sidebar) — a source picker + the inline directory browser, no detected-dirs list, no recents (the browser IS the picker). The source picker lists every environment with its host glyph and a tick on the current one, and ends with an **Add Environment** escape that hands to the pairing dialog. Switching source clears the selected path and reloads the browser against that host's filesystem. Add is inert until a folder is selected; the dialog reopens clean each time. Adding produces no orchestrator turn (the sidebar state carries it) and navigates straight to `projectIndexingPath(id)`.
- **Directory browser — REUSE `components/directory-browser.tsx`** (already vendored, already fed by `fs.listDir`), not the spike's port. It carries the clickable breadcrumb (current segment inert), an Up control inert at root, a typed path bar that navigates on Enter, row-click descent, arrow/Enter/Backspace keyboard nav, a "repo" badge on repo folders, dimmed `aria-disabled` unreadable folders, an inline alert on an invalid typed path, "No folders here" on empty, stale-listing guard, and `listbox`/`option` roving-tabindex semantics. Any §10.2 claim the shipped component does not yet satisfy is closed in-place, in the reused file.
- **Add Environment pairing dialog** (`ui.openDialog("add-environment")`) — address + one-time code (never a bare code); the code field's helper names `rennet pair` and states the printed link fills both fields. Connect inert until both fields carry a value; fields lock + spinner while connecting; on success it names the machine and offers Done and **Browse Its Projects** (reopens Add Project with the new environment preselected). Clean reopen each time; environment name derived from the address's first label. (Reuses the existing host/pairing machinery C3 left untouched — no new preload or supervisor work.)
- **Project indexing view** (`/projects/:id/indexing`) — the single surface where everything after Add happens (no live-filling map). It runs the **scout phase before context-map generation**: read git remotes (naming the forge origin), check tracker markers + CI config, scout reads README/CONTRIBUTING/agent files, scout returns stating how-many-detected / how-many-guessed. The deterministic pass runs before the model-backed scout seat. The header status reads scouting → indexing → indexed. Generation starts exactly when the scout returns.
- **Prefilled questionnaire** — appears the moment the scout returns, while the map generates beneath it (**never a gate** — the map completes and exits appear whether or not it is answered; Rule Zero). Heading asks whether the prefilled answers look right and states skipping is fine and everything stays editable in Settings. Prefilled answers: issue tracker, default branch, worktree location, gate command, logo/mark — each with a **provenance chip** ("detected" neutral / "guessed" in the machine register) and a one-line hint naming source and use. Fixed-option answers render as segmented picks; the rest as editable monospace inputs. Escape inside a field blurs it (never leaves the view). One action, "Looks right", collapses to a saved-and-editable confirmation line. The mark is a cosmetic answer that never enters agent context.
- **Map generation with progress + exits** — steps appear only once started, spin, then tick: scanned the working tree (file/scope counts), mapped imports across scopes, knowledge workers reading scopes (live N/M + hypothesis count), verifying hypotheses against cited evidence (confirmed/rejected — the human is never a gate on it), connected the dots. Leaving early (back/Escape) does not cancel; the sidebar row's spinner stays synchronized with the processing timeline. On completion a "Context Map Ready" block states scope/file/confirmed-rejected counts, its only action **View Context Map** (→ `projectMapPath`). A full-width **Start a Review** CTA sits below it as the flow's primary exit (→ New Chat on the just-added project), scrolling itself into view at the bottom of a scrolled timeline. **The spike's simulated 10.5s `setTimeout` timeline (autopsy S9) is not ported** — progress is driven by the real `project.process` `onProgress` channel via `useCommandStream` (fixtures behind `MemoryBridge` until the live generator serves it).
- **Context-map view** (`/projects/:id/map`) — a standalone full view. **REUSE `context-map/model.ts`** (`buildScopes`, `knowledgeForSelection`, `Selection`) over `project.contextMap`. Base line names repo/ref/object-id with a "● current"/"◐ building" freshness chip; structure pane lists scopes (importer + file counts, header totals), expandable to sample files; the dependency neighborhood is an SVG (selected scope centered, importers left, imports right, arrowed edges), nodes clickable/keyboard-activatable to re-center; an edgeless scope says so; Knowledge/Details tabs (knowledge shows statement count; each statement shows subject/confidence/status/claim/evidence anchors; proposed offers confirm/reject/discuss via `project.knowledgeDisposition`, confirmed/rejected drop controls and a rejected statement dims not disappears; a nothing-learned scope says so; Details lists name/root/file/test counts + imports/importers). The shipped ask-rail is absent (the session chat column plays that role). Leaving the map always lands on that project's New Chat. C12 wires the entry points it owns (new-chat header, ready block); the sidebar context-menu entry is C3's, the command-menu entry is C11's.
- **New Chat view** (`/new-chat?project=…`) — a full-view takeover with no chat column (no session exists yet): header with back arrow, `project › New Chat` trail, a Map control, and an `esc` hint; Escape closes the page. Headline "What should we review in <project>?" with the project name as a headline-sized inline picker (changing it resets the target and updates the URL). Composer carries a target chip (X resets to current checkout); Send inert while empty. **The smart list — REUSE `project/smart-list.ts`** (`buildSmartRows`/`filterSmartRows`/`sortSmartRows`/`smartListCounts` over `project.detail`): one list, no zones, state gives a row its look; tabs All / Needs you / Mine / Local / PRs with live counts; text filter over PR number/title/branch/repo/author (or branch+repo for local); Escape clears the filter first, closes on the second press; "Current Checkout · main" pinned first as the default target; local rows (mono branch, "● dirty" mark, accent glyph when dirty, note, state chip); PR rows (title, CI, state chip; second line: number, branch, author, colored +adds/−dels, file count, "checked out locally" chip; CI collapses to a dot except a failing "CI failing" chip); the unified target-vocabulary state chips (Needs you / Merged / Reviewed / Your PR / Teammate PR / Your branch); merged rows dim + lift on hover; the repo column drops for a single-repo project; the selected row is ticked, not striped; empty/filtered-empty copy. **A row click starts the session — not merely target selection (R26)**: it mints a real session, derives the title from the target, carries the typed ask in as the first turn, claims that target so the row **vanishes from New Chat**, and lands in the session.
- **`/archived`** — the archived-sessions view: restore returns a session to the live sidebar; **release is archive-only** (the New-Chat row reappears once its session is archived — the target is reclaimable).
- **Simulated timelines removed** — the fake timeline never existed in `app-ui`'s store (it lives only in the spike's `lib/store.ts`); C12's obligation is to bind the real `project.process` channel and never reintroduce a fake one.
