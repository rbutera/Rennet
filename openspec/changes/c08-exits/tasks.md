  - stage ↔ unstage: `stageAsk(ask)` / `unstageAsk(anchor)` add/remove the `stagedAsks[anchor]` entry.
  - Drop / Delete / retire ↔ Restore: `retire(ask, reason)` appends the WHOLE ask (intent/source/anchor) to the `retired` ledger and the surface unstages it; `restoreRetired(anchor)` drops the ledger entry and the surface re-stages the kept ask. Nothing is destroyed — the retired ask is held intact for restore.
  - verdict override ↔ "use proposal": `setVerdictOverride(v)` sets a nullable overlay; `setVerdictOverride(null)` reverts, and the proposal is always re-derived from `verdictArithmeticFromAsks` (never stored). An approving override is first-class and equally revertible.
  - Edit: `setDraftEdit(anchor, body)` writes a `draftEdits[anchor]` OVERLAY; the source `ask.body` is never mutated (`blockText` falls back to it), so the original reads back and a later edit overwrites cleanly.
  - The ONLY irreversible act is the final sign-click egress (`publish.review` / `publish.submitPr`) — it leaves the machine. Everything up to it is transient store state; leaving/reopening the hand-off loses nothing (the durable-across-reload guarantee is B11's, cluster 8). No store mutation in the hand-off path posts or destroys.
