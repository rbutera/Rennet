# C8 — Hand-off & exits: the exit FAB, the ask basket, the hand-off view, the living draft, and the three exits (#489)

## Why

INVENTORY §6 carries ~70 `[ws:C8]` claims — the review's **leaving** surfaces. A review ends by going through an exit: the posted GitHub review, a dispatched work-order round, or the opened pull request (`docs/developing/concepts/handoff-and-exits.md`). Everything the reviewer concludes gathers as **asks**; a gold FAB carries the live basket count; a view toggle opens the hand-off, whose lanes depend on the entry mode; the outbound documents stay drafted; and one explicit click posts. C8 is the surface that turns C5's board reading and C6's diff reading into a submitted review.

The autopsy (S8, #489) named the spike's central exit defect: the flight/pip animation rode a **module-global emitter** (`lib/fab-signal.ts`) whose state **does not travel** — a fresh mount, a second surface, or a projected client loses it, and the pip count drifted from the review because it was *accumulated from events* rather than *derived from content*. C8's spine is the inversion the C01 store already set up: the pip count is a **selector over the `review` slice** (staged asks + unclaimed line comments + unclaimed quote threads, Explain excluded, an ask claiming the thread it was born from so a highlight request-change counts **once**), so it reads the same after any navigation because nothing stores it. The flight/pop *gesture* rides the `signal` slice's batched counters, not a module global. That is the reason this is a rewrite, not a JSX port.

## What Changes

All new work in `packages/app-ui/src/handoff/` (new), rendering over the **already-landed** C01 store slices (`store/review.ts` — `stagedAsks`, `retired`, `verdictOverride`, `draftEdits`, `quoteThreads`; `store/signal.ts` — `inFlight`/`landed` + `selectSignalAnimating`), composing C4's `review/` components (`ProseSelectionLayer`, `RichText`, `AnchorReveal`) and reusing `packages/ui` primitives. **Zero new dependencies** (`lucide-react` glyphs are already an `app-ui` dependency). The client **invents no review shape locally**: staged asks are the `StagedAsk` the store owns, and the outbound bytes come from the registered `publish.*` commands, never a client-fabricated post.

- **`handoff/handoff-data.ts` — the hand-off resolution seam, one resolution point (mirrors C3's `sidebar-data.ts`, C4's `citations.ts`, C5's `board-data.ts`).** The single module that resolves (a) the **entry mode** for a review — teammate-PR / own-branch / retrospective, keyed on the `Review` domain's `postTarget` presence and branch state — and (b) the **living-draft source**: the ordered review-body blocks + line comments the lane renders. Today the draft is composed from the store's staged asks (the review's own acts) and, where a review can post, the registered **`publish.compose`** command through the bridge (its comments/verdict/payload are the daemon's, single-source with the post). B11's continuously-redrafted durable composition projection and the real span-**rework** command are the one swap this seam absorbs when they land (gated cluster 8). Every hand-off path goes through it.
- **`handoff/selectors.ts` — the derived exit arithmetic, beside the `review` slice (Objective clause 7).** The store holds state; C8 adds the selectors that were the spike's scattered `useState`/`useMemo`: `selectExitPipCount` (asks + unclaimed line comments + unclaimed quote threads; Explain threads and any thread **claimed** by a staged ask's `threadId` excluded — the "counts once" rule, R50 amendments), `selectProposedVerdict` + `selectVerdictArithmetic` (any request-change ⇒ Request Changes; any other ask ⇒ Comment; nothing ⇒ Approve; with the `N request changes · M comments` tally), and `selectBodyVsLineAsks` (an ask whose anchor is a `path:line` code position becomes a **line comment**; an anchorless/prose ask travels in the **review body** — R36, no chrome copy). **Derive, don't store** (the store discipline): a field a selector could compute is a bug.
- **`handoff/fab.tsx` — the exit FAB + the single pip + the flight (Objective clause 1, autopsy S8).** A gold pill-shaped floating action button, bottom-right of the view region; **target-aware label** ("Write Review" on a teammate PR, "Continue" on your branch or PR — R35 amendment), the label dropping below 54rem of pane width to icon+count. It **toggles the hand-off view** and **yields** (shrinks, fades, `pointer-events: none`) while the hand-off is open (R49). A single deep-red count **pip** from `selectExitPipCount` — no inline "· n" in the button text (R50 second amendment); the accessible name carries the count. Staging flies a small red bubble from the **acting element** (recovered from focus, never wired per call site — R50) to the FAB over ~420ms; the **pop rides the gesture** (the flight landing, or immediately when there is no source), never the count, so route transitions and seeding never animate it. Composite actions **batch inside an ~80ms window** and collapse to one bubble via an **injected-clock batcher at the call site** (the `signal` slice comment's contract — no RxJS); a genuinely later orchestrator event falls outside the window and pips on its own. This is the named replacement for `lib/fab-signal.ts`'s module global: the count is derived, the gesture is the slice's `launch`/`land`.
- **`handoff/ask-basket.tsx` — the staged-ask basket + staging receipts (Objective clause 2).** The staged unit is an **ask**: text, intent (comment / request-change), a provenance source, an optional diff anchor, an optional originating thread (`StagedAsk`, R29). Findings **never auto-stage** — staging is always an act (C5's finding renderer and C4's toolbar already call `reviewActions.stageAsk`; C8 renders the basket and the undo). Every staging control is its own **receipt and its own undo** (`unstageAsk`).
- **`handoff/handoff-view.tsx` — the hand-off view toggle, dispatched by mode (Objective clause 3).** The hand-off is a **view toggle on the review workspace, exactly like the board and diff** — a third `?view=handoff` branch on the route that C5/C6 already partitioned (Reconciliation 1). It dispatches by entry mode: teammate PR ⇒ the Post Review lane; own branch ⇒ the rounds lanes; retrospective ⇒ no exits. The FAB toggles it; the board/diff switch stays reachable and leaving returns to the reading view.
- **`handoff/post-review-lane.tsx` — the Post Review lane, teammate-PR mode (Objective clauses 4, 5).** Heading "Post Review · <PR ref>" with a pull-request glyph. The **verdict segmented control** — Approve / Request Changes / Comment, each with a status dot — is **proposed, not derived-and-locked** (R33): `selectProposedVerdict` proposes, the control states its arithmetic beside it ("proposed from your review · N request changes · M comments"), it is always flippable, and an overridden verdict says so and offers **"use proposal"** to revert (`setVerdictOverride(null)`). An approving review is first-class. The **living draft** renders in **GitHub's two-strata shape**: a sans-face review body (R40) with the opener + one block per body ask (intent tag + provenance line above its prose, `RichText`), then **line-comment cards grouped by file path**, each with its click-to-reveal `AnchorReveal` anchor, its intent tag, and hover/focus **Edit** (inline textarea, Cmd/Ctrl+Enter saves, Escape cancels) / **Delete** (retires to the ledger and unstages its ask — `retire` + `unstageAsk`). The draft is rendered **exactly as it posts — no separate preview stage** (R31, #435). A bare residue line ("N threads · M code comments stay local" — no reassurance clause). The **Retired drawer**: each retired block struck through with its reason and a **Restore** control that re-stages it with its original intent/source/anchor (a restored opener returns as an override, not a re-staged ask). No copy about freezing or consent (law 10).
- **`handoff/rounds-lanes.tsx` — the rounds lanes, own-branch mode (Objective clause 3, R37).** One goal in two states, the page's shape stating which: while asks remain, the surface is **Changes** (ask count beside the heading; one card per ask — intent pill, provenance, text, anchor reveal; **Dispatch Round** beneath, inert while nothing is staged) and the pull request is a single **muted destination line** at the foot; when nothing is left to ask and the PR is ready, the surface **IS the pull request** — title as heading, drafted description (the `## `-heading + bold markdown subset through the same `RichText` pipeline), **Open Pull Request** primary. No "This Round" wrapper, no "ripening" language (law 10). With no asks and an unripe PR: "Nothing staged yet." Work orders are own-branch only; a teammate PR never offers a rounds lane; there is no self-review lane.
- **`handoff/handoff-action.tsx` — the one exit CTA, shared by both modes (R31).** A full-size action that shows the submission **in flight** (full contrast, not dimmed) before the lane swaps to its **receipt** — the posted review (verdict, line-comment count, body, a link to the posted review) or the opened PR (number + link).
- **Selection is the steering wheel (Objective clause 4, 8).** Draft prose selection offers **Revise / Drop / Explain** through C4's `ProseSelectionLayer` (the same `DraftHandlers` seam C4 exposes): **Drop** retires the span to the ledger and unstages its ask (real, `retire`+`unstageAsk`); **Explain** answers with the span's provenance (real, over the `review` slice); **Revise** takes a free-text instruction and reworks the span — the spike's string-surgery `applyRevision` is replaced by the **real rework command through `handoff-data.ts`** (gated on B11, cluster 8; the affordance renders, the execution is the seam). A reviewer's revision wins over regeneration. The reviewer **never types into the draft** (R32) — steering is by selection.
- **Preview → direct Post, on explicit click only (Objective clauses 6, 10).** The draft above **is** the preview; Post acts on it. Post Review resolves through the registered **`publish.compose(mode:"review")` → `publish.review`** (dry-run default; real egress only on the explicit sign-click, the bytes round-tripped); Open Pull Request through **`publish.compose(mode:"pr")` → `publish.submitPr`**. Nothing another human can see leaves without the click. **Receipt-is-undo throughout**: every drop, retire, delete, and verdict change is reversible; only the final action is not (and it is the click).
- **`handoff/index.ts`** barrels exactly the public surface (the FAB, the hand-off view, and any type a consumer needs) and `app-ui/src/index.ts` re-exports it; `review-workspace-route.tsx` gains the `?view=handoff` branch and mounts the FAB.

## Reconciliations against main (packet drift, recorded per the dispatch rule)

1. **"Hand off = view toggle … exactly like Map and Diff" — the route is now a `?view` switch, not the spike's `main-surface.tsx` tab bar.** C5 and C6 landed **today**: `packages/app-ui/src/app/review-workspace-route.tsx` reads `?view` and renders C6's `DiffViewContainer` for `?view=diff`, else C5's `LensBoardView` (the default). The spike's `main-surface.tsx` (which the INVENTORY claims cite) does not exist here. So C8's hand-off is a **third `?view=handoff` branch** on that same switch, and the FAB is what toggles to it — the packet's "view toggle" intent, expressed in the route shape C5/C6 established, not a ported tab bar. The board/diff pill stays reachable; leaving the hand-off returns to the reading view.
2. **The store slices are already landed (C01) — C8 adds selectors and surfaces, it does not re-create state.** The packet's "rewrite everything stateful: verdict arithmetic, ask claiming, pip counts, retired ledger become **selectors**" is exactly the C01 discipline: `store/review.ts` already owns `stagedAsks`/`retired`/`verdictOverride`/`draftEdits`/`quoteThreads` and `store/signal.ts` owns the flight counters. C8 **adds the derived selectors beside them** (`handoff/selectors.ts`) and the surfaces that read them — no new slice, no duplicated field. The spike's `useCodeComments()` god-store and per-component `useState` are the thing being deleted, not ported.
3. **The exits wire LIVE through registered, bound commands — this is a narrower gate than C5's board.** Unlike C5 (no board-fetch command is registered, so the whole live read was gated), `publish.review`, `publish.submitPr`, and `publish.compose` **are registered in `packages/protocol/src/commands/index.ts` and bound in `packages/server/src/dispatch/publish.ts`** (dispatch tests exercise them). `useCommand` (`app-ui/src/data/query.ts`) can name them, and the `MemoryBridge` answers them. So the Post / Open-PR **egress and preview compose are real** (dry-run default, real on the click) — not gated. What **is** gated (cluster 8) is narrower: B11's **continuously-redrafted durable composition projection** (the living draft that survives reload) and the real **span-rework** command behind Revise. The Dispatch-Round **button** is C8; the live **round run** it navigates to is C9 (out of scope).
4. **The spike's `lib/fab-signal.ts` module global is deleted, not ported (autopsy S8).** The flight/pop gesture rides the C01 `signal` slice's `launch`/`land` with an injected-clock 80ms batcher at the call site (the slice's own documented contract — no RxJS); the acting element is recovered from focus. The durable **count** is `selectExitPipCount`, derived from the `review` slice — never the accumulated event total the module global held.
5. **The spike's `streaming-prose` and `coachmark` are spike-only chrome — dropped.** The draft renders through C4's `RichText`; "streams its block in" is a transient nicety tied to the live redraft (folded into B11's living draft, cluster 8), not a ported `StreamingProse`. Coachmarks/tour scaffolding are not in the packet and are not built.
6. **Two ask shapes, kept distinct.** The store's `StagedAsk` (anchor/type/body/threadId) is C01's in-flight renderer shape C8 renders over today; the protocol `AskSchema` (intent/exitLane/provenance/lifecycle, `session/model.ts`) is the durable/session shape. C8 renders the store shape; B11/B9's durable ask projection is part of the cluster-8 swap the `handoff-data.ts` seam absorbs. Body-vs-line routing keys on the `StagedAsk` anchor being a `path:line` code position (the spike's `codeAnchor` presence), per R36.

## Fix-loop amendments (PR #530 dual review — Codex + opus, 8 upheld)

The fix loop resolves 8 upheld findings (2 critical), records 2 deferred-with-record, and honors 1 parked-for-Rai. One amendment per finding, in fix order.

- **A1 — Exact-preview: the previewed review IS the posted bytes (critical, Reconciliation 3 sharpened).** The lane rendered the store's working set (`stagedAsks` + `draftEdits`) while `onPost` recomposed from the daemon on the click and posted THAT — the preview and the payload could diverge, violating architecture-contracts.md "Posting to GitHub" (R31/R33). Now `useHandoffExits` composes `publish.compose(mode:"review")` **on open** (stable command id; enabled only in teammate-PR mode) and exposes `reviewDraft`; the Post Review lane renders a new `ComposedReviewPreview` over exactly those composed bytes (read-only — they are the outbound payload, not the working set), and `onPost` posts the SAME `reviewComposed` (payload + comments + compositionId), never a fresh compose. The CTA is armed only once composed (disabled until then — honest). Because `publish.compose` takes no inline-edit input, any local `draftEdits` cannot reach the composition, so the preview marks them **pending-not-applied** (named, never silently dropped); refinement happens in the diff/working surfaces before compose, and reopening the lane recomposes. `exits.dom.test.tsx` now proves compose fires on open (a read; nothing leaves), the preview renders the composed comment bodies and NOT the store ask bodies, the sign-click posts the byte-exact payload+comments without re-composing, and an unreachable inline edit shows the pending mark while the posted bytes stay byte-for-byte the composition.

- **A2 — Review-identity isolation: the `review` slice resets on a review switch (critical, C05's boardId lesson applied).** The store is a singleton (`store/index.ts`) and `review-workspace-route.tsx` never keyed or reset it on `review.id` change, so review A's `stagedAsks`/`retired`/`draftEdits`/`verdictOverride` contaminated review B — and A's override became B's submitted verdict. `ReviewWorkspace` now resets the `review` slice (via `resetReview`) when `review.id` changes, keeping nothing across identities — the same inversion C05 made for the board (`viewed-delta` keyed on `boardId`, the document subtree remounted on `boardId`). It resets ONLY on a real id change, never on first mount, so a seed-then-mount (fixtures and the finding-1 pending-mark test rely on this) is preserved. `review-identity.dom.test.tsx` mounts A, stages asks + overrides the verdict, switches the prop to B WITHOUT calling `resetReview`, and proves B's FAB pip is empty and the slice (asks + override) is clean; a second case proves first mount does not wipe a seed.
