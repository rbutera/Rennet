# B06 — context-map-swarm (#460: partitioned knowledge swarm on the Model Council)

Packet: `context.md` (scope authority). Plan row B6. Blocked-by B3 (landed). Authored 2026-08-27 against main @ 4fad6d62 (B05 landed, C01 merged).

## What this change does

Implements #460's resolved architecture, replacing the single flat knowledge pass (the `DEFAULT_KNOWLEDGE_MAX_FILES = 400` git-order cap and its silent ~10% coverage):

- **Partitions are invisible plumbing** (`core/knowledge/`): one worker slice per workspace scope from the structural map (`project-context.ts` scopes); oversized scopes subtree-split under a ~120-file per-worker cap; plain directory split when scope detection finds nothing. Coverage total by construction — every in-scope file in exactly one slice. No partition-shaped artifact survives the run.
- **Light-tier workers emit full statements at the edge**: the existing statement schema with the shipped mint-time honesty contract (anchors resolved to blobOids from the snapshot inventory, anchor-or-drop, hypothesis label) plus one optional free-text `hint` for the synthesizer — discardable, never stored.
- **A verify/synthesis seat confirms hypotheses itself** (human confirm stays an optional override, never a gate — Rai's ruling + Rule Zero): re-reads each hypothesis's cited spans (bounded by anchors, not a repo re-read), flips to `confirmed`/`rejected`, mints the cross-cutting statements no single worker could see, dedups.
- **Incremental thereafter**: on baseline advance only workers whose slice contains changed paths re-run; the verify seat re-adjudicates only statements whose cited evidence changed; everything else carries verbatim; cross-cutting statements re-verify when any cited path changed.
- **Knowledge stops bypassing the Model Council**: `partition-worker` (light) and `map-verify` (heavy seat, medium-class model) enter the three versioned assignment tables in `core/model-council.ts`; adapters resolve the assignment and run the turn on the resolved harness (cheap Codex for the light volume in the both/codex-only scenarios, per R39).
- **No cost cap** (decided): the swarm path takes no `InvocationBudget`; R10 stays intact for every other model path.
- Scheduling lives in `server/runtime/` (new), with per-partition progress lines (queued / running / statement counts) and the verify stage as its own line.

## Out of scope (consume shapes only)

Lens agents consuming statements (B8); project-scout (B7); the context-map UI (C12). `KnowledgeStatement`/`KnowledgeSet`/`KnowledgeAnchor`/`KnowledgeStatus` and the council manifest ids are B03-frozen protocol contracts — consumed, never re-modeled.

## Review-fix amendments (PR #517 round 1)

13. **Partition isolation enforced at mint.** `runPartitionWorker` resolved anchors against the whole snapshot inventory, so isolation was prompt-only. The worker's anchor index is now built from `slice.files` — an off-slice citation drops by the same anchor-or-drop rule as an invented path. The verify seat keeps the whole-inventory index (cross-cutting statements span slices by design).

14. **Ownership keyed by scope root, not name.** Two scopes sharing a name previously merged into one group and emitted its files once per same-named scope, breaking exactly-once coverage. Grouping now keys on the root (the identity prefix matching actually uses); slice ids stay the scope name where unique and become `name:root` on a name collision; a fully duplicated scope entry collapses to one group.

15. **`routeDelta` learns prior ownership.** A deleted path (or one whose ownership moved with the scope graph) has no current owner and previously routed zero workers. `routeDelta` now takes the prior partitions: an orphaned changed path routes the current slices in its prior owner's id family (equal id, or split-boundary prefix drift). A path whose prior family vanished entirely still routes nothing — `planReverify` re-adjudicates every statement citing it, which is the safety net for a scope that no longer exists.

16. **Re-verify entries are re-anchored; fresh verdicts are never overwritten.** `planReverify` now accepts the new snapshot's file inventory: each re-verify statement's anchors are restamped with current blobOids (an anchor whose path vanished is dropped), a statement whose evidence thereby changed gets a fresh id and returns to `hypothesis` (its prior verdict was about bytes that no longer exist), and a statement with NO surviving anchor lands in a new `invalidated` bucket — it dies with its evidence, never carried as completed work. `dispositionCarrier` now lifts only statements still labelled `hypothesis`: a verdict minted in the current pass outranks the stale disposition.

17. **Codex seats are rooted at the checkout (P0).** The codex utility executor deliberately ran in a temp dir, so a Codex-routed worker or verifier reasoned from filenames alone — it could never read its evidence. `CodexExecRequest` gains an optional locus-native `cwd` (absent ⇒ the classic temp-dir utility posture, unchanged for every other caller); the swarm's turn builder passes the repo root, matching the Claude seat, and the worker prompt now instructs reading the slice files. Chosen over inlining blob contents into prompts: the turn surface already plumbs `cwd` end-to-end (thread + turn params, full-access sandbox), the agent reads exactly what it needs instead of the swarm shipping ~120 files of text, and both harnesses share one evidence story.

18. **A git failure is a failed pass, not a silent skip (P1).** `changedPathsBetween` swallowed every git error into `[]`, which the runner reported as a successful "no changed paths" skip — dropping the missed interval. It now throws; the runner maps the throw to a typed `failed` outcome the scheduler's existing retry path handles.

19. **The runner owns its mode; caller `fromOid` is gone (P1).** The delta base now derives from the STORED prior set: same generator+schema at the current baseline ⇒ skip; at an older baseline ⇒ incremental from `prior.baseOid` (prior ownership for orphaned paths reconstructed via `git ls-tree` at that OID, re-verify entries re-anchored against the current inventory); a foreign generator or schema (the retired flat pass's `knowledge-gen@1`) ⇒ full replacement, never carry substrate. `fromOid` left the deps, the scheduler input, and the rehydration bookkeeping; the CLI's own prior/`fromOid` logic collapsed into the runner's decision.

20. **The initial run is scheduled, not implied (P1).** `startRepoRehydration` now kicks one knowledge run when the watcher starts (the swarm's already-current skip makes this idempotent across launches), so a freshly-processed project gets its first map without waiting for a baseline advance — amendment 10's "initial + baseline-advance" claim is now true in code.

21. **All-or-keep-prior (P1).** Any failed partition worker now fails the whole run and leaves the store untouched — a persisted set silently missing a failed slice's knowledge would read as complete work. The scheduler's retry re-runs the delta.

22. **Statement provenance names the seat that ran (P2).** `HarnessTurnResult` gains optional `observed` model/credential facts; both turn builders fill them (Claude from `session.started`, Codex from the exec result's observed model with the requested model as fallback), the runner seeds each seat with its council-resolved model, and mint stamps observed-over-seed — worker statements name the worker's model, cross-cutting statements the verifier's.

23. **The packet E2E runs the production orchestration (P1).** The synthetic core e2e (regex-derived scopes, hand-merged helper outputs, one snapshot) is replaced by an adapters e2e driving `runKnowledgeSwarmForRepo` over a REAL temp git repo with two commits, real `ProjectSnapshotGenerator` snapshots, and stub turns: exactly-once coverage from the real scope graph, resolving anchors, an advance re-running only the owning partition with byte-identical carry, and the all-or-keep-prior guarantee under injected partial failure.
