# B4 — Boards runtime: the embedded board store, its privacy seam, and the only writer (#489)

## Why

B3 froze the board contracts (13-kind host schema, LensBoard projection, wire schema) but nothing runs them: there is no board store, no event log, no way to apply an op. B4 lands the runtime floor the lens pipeline (B8) writes into and the client (C5) reads from: `@wboard/server` embedded in-process (engine asset §3 — Rennet does not write its own event-log engine), an append-only event log persisted under `.rennet/` (local, never staged), board events and projections privacy-wrapped by the same `projection.ts` seam that already guards every remote broadcast, and `adapters/whiteboard-client.ts` — the five whiteboard tools, the only writer of board ops.

## What Changes

- **`packages/server` gains `@wboard/server@0.1.0-alpha.2`** (exact pin, MIT, dep `@wboard/core@0.1.0-alpha.2` — already installed via protocol). Verified against the published tarball, per the packet's gate instruction: it ships the embeddable `BoardService` class (create/getSchema/describe/getEvents/getState/apply with op_id dedup, all-or-nothing validation, per-board write serialization) over a **pluggable `BoardStore` interface** (createBoard/getSchema/append/getEvents + `AppendEntry`), whose own JSDoc names it "the seam Rennet's B4 plugs its own storage into", plus the pure `project()` fold and `InMemoryBoardStore` reference. The A3 SPEC requirement holds; the packet's STOP-and-escalate branch is dead.
- **`server/boards/`** — the boards runtime: a `FileBoardStore` implementing `BoardStore` with an append-only JSONL log + schema document per board under `.rennet/boards/<boardId>/` (Node stdlib only, per the store contract; contiguous seqs; copy-on-read/write ownership honored; restart = replay), and a thin runtime that owns one `BoardService` over it, creates boards with the Rennet host wire schema (`BOARD_WIRE_SCHEMA` from `@rennet/protocol`), and feeds board events into the server's existing push path. No freeze/generation policy here — append-then-freeze lifecycle is #457 policy owned by the pipeline/session workstreams (B8/B9); the runtime stores whatever boards it is told to.
- **`adapters/whiteboard-client.ts`** — the five #455-locked tools (`create`, `schema`, `apply`, `describe`, `events`) as a typed client over an injected `BoardService`, **the only writer of board ops** in the codebase. Op-id minting surfaced so callers get #453's replay-idempotency for free. No transport, no MCP facade — in-process, the same shape the B8 drafters and orchestrator will call.
- **`server/projection.ts` promoted, not forked** — KEEP as-is; new `projectBoardEvent`/`projectBoardProjection` wrap board events and projected board state with the existing scrub walker before any broadcast to a `projected` connection (board data carries absolute paths in prose/json attributes; loopback stays raw, same split the module already implements). Positive control: a board payload containing an absolute host path or home-dir string must be caught by the privacy-wrap test.
- **Docs in the same change:** `architecture-contracts.md` (board persistence under `.rennet/boards/`, the promoted projection seam), `architecture-overview.md` + `monorepo-map.md` (server + `@wboard/server`, adapters' whiteboard-client), grep sweep.
- **Out of scope (packet):** the lens pipeline that fills boards (B8); client rendering (C5); dispatch/commands work — `patchset.readSpan` stays unbound (see reconciliation 6).

## Reconciliations against main (packet drift, recorded per the dispatch rule)

1. **`@whiteboard/server` → `@wboard/server@0.1.0-alpha.2`** (published scope; B03 precedent). The packet's embeddable-with-pluggable-persistence gate was verified by reading the published tarball's `.d.ts`, not by trusting the retired-risk note.
2. **`minimumReleaseAgeExclude` gains `@wboard/server`**, name-scoped, same first-party rationale and comment style as the `@wboard/core` entry B03 added (SDK precedent).
3. **Adapters dependency (flagged to the dispatcher before implementation):** the engine asset's edge list puts `@wboard/server` on `server` only, but `whiteboard-client.ts` needs the `BoardService` type. Proposed: `packages/adapters` adds `@wboard/server` as a dependency used type-only (plus `@wboard/core` wire types), and the server injects the live instance. The alternative — re-declaring a structural five-method interface in adapters — re-models a published contract, which B3 established as a defect.
4. **"create canvas" (packet verification wording) → `createBoard`.** #457 locked the vocabulary: canvas is dead, board is the store. The E2E uses board terms.
5. **Five tools, not six.** #455's locked surface is create/schema/apply/describe/events "+screenshot"; `BoardService` has no screenshot (it is a render concern with no headless backing) and no consumer exists until C5. The client ships the five; screenshot arrives with the render target that can produce it.
6. **`patchset.readSpan` stays unbound.** B03's reconciliation 8 said "dispatch binds it in B4/B10". B4's packet scope is the board store, not dispatch; binding lands with B10's registry-bound dispatch rebuild. The B03 throwing case stands unchanged.
7. **Broadcast rides the existing push path.** The packet says "broadcast projections"; the server already owns a live-event push machinery and the loopback/projected connection split. B4 feeds board events through that path (wrapped for projected connections) rather than building a parallel channel. The implementer inspects `create-server.ts`'s push/live-event registry and reconciles to its actual shape, recording the wiring point.
8. **(Cluster-4 amendment) The broadcast needed a wire frame and a construction seam.** `session/wire.ts` gains an additive `boardEvent` frame in the `SessionFrame` union, its payload `@wboard/core`'s published `EventSchema` (the store's own wire shape, not a re-model); the client's frame parser accepts it and its switch ignores it until C5 subscribes. `RennetServer` gains `boardsRuntimeFor(projectRoot)` — one runtime per project root, its store-append hook bound to `broadcastBoardEvent` — the seam B8's pipeline writes through. Both are the mechanical minimum of "board events flow to connected clients"; no new transport channel exists.
