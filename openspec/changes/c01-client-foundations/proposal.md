# C1 — Client foundations: data seam, router, store, MemoryBridge (#489)

## Why

Every later Track C change renders through four seams that do not exist yet. Today `packages/app-ui` consumes `RennetBridge` as a prop threaded into `app/shell.tsx`, which fires `bridge.invoke` from effects and body functions, holds every screen as a nullable-state cascade, and navigates through a bespoke `Surface`-stack (`app-ui/src/nav/history.ts`) whose grammar does not match the decided URL contract (#480). There is no store — interaction state lives in component memory — and no test bridge, so fixtures would have to be imported as modules, the exact anti-pattern the spike autopsy names (S1 fixture imports, S3 god-component state, S9 prop-drilled data). The client asset (§2–4, [#489 comment](https://github.com/rbutera/rennet/issues/489#issuecomment-5431046569)) specifies the replacement; C1 builds it thin and gets it right, because C3–C14 all stand on it.

## What Changes

Four foundations, one directory each, plus the cutover that makes them real.

- **Data seam — `app-ui/src/data/`** (client asset §3). `bridge.tsx`: `BridgeProvider` + `useBridge()` context replacing prop-threading. `query.ts`: `useCommand(name, input, opts) → {data, error, pending, stale}`, cache keyed by command name + canonical input. `stream.ts`: `useCommandStream` subscribes a push channel (`onProgress`, `onProjectDetailProgress`, `onAskStream`, `onAttention`, `onUpdateReady`) and writes events into the same cache entry, so a component only ever reads one thing. `mutate.ts`: `useMutation(name)` → invoke + invalidate by key prefix. **Standing law: no component calls `bridge.invoke` directly** — enforced by lint, with every existing direct call site in `app-ui` migrated onto the hooks in this change so the rule ships with zero exceptions. The cache is an explicit decision: evaluate `@tanstack/react-query` against the [dependency standard](../../../docs/developing/reference/dependency-standard.md) admission test; if rejected, the ~120-line module-level `Map` + `useSyncExternalStore` fallback behind the SAME hook surface, so the swap stays internal either way.
- **Router — `app-ui/src/routes/`** (client asset §4, #480). A real router with an **injected history** — the host supplies it exactly as it supplies the bridge: hash history in Electron (`file://`, `apps/desktop/src/renderer/index.tsx`), browser history in the served tab (`apps/desktop/src/browser/entry.tsx`). The #480 route table: `/` → `/new-chat`, `/s/:slug` (+ `?view=diff|map|handoff|rounds`, `?lens=`, `?file=`), `/s/:slug/run`, `/archived`, `/projects/:id/indexing`, `/projects/:id/map`, `/settings/:page` (+ `?project=`). Layout route owns sidebar + chat-dock slot **outside the outlet**, so navigation never unmounts them (risk 4); view toggles use `replace`, screens use `push`; unknown `?view`/`?lens` fall back rather than error. `app-ui/src/nav/history.ts` (the `Surface` stack, `PersistedNavState`, and its persistence) is retired — back/forward becomes real history; reopen-where-you-left-off, if wanted, is a later "last URL in client-settings" item, not this change.
- **Store — `app-ui/src/store/`** (client asset §2, packet). One zustand store (`zustand@5.0.14`, already a dependency), slices `ui` / `review` / `run` / `signal`, **no persist** — reload means the URL restores location and interaction resets clean. Selectors live beside their slice; **derive, don't store**: counts, highlights, and proposals are selectors over projection + store, never fields. **No `sidebar` slice** — the host/project/session tree is a server projection and every mutation is a command; what remains of the spike's sidebar slice is fold state, which is `ui`.
- **Test rig — `app-ui/src/test/`**. `MemoryBridge implements RennetBridge` (`packages/protocol/src/wire.ts`): typed per-command handlers, loud rejection of unhandled commands, emit helpers for the five push channels. Fixture data becomes fixture *bridges* under `src/test/` — nothing under a surface directory can import a fixture, because the data only arrives through the bridge context. This makes INVENTORY §13 self-enforcing, and a fence test proves it.
- **Cutover.** `RennetApp` mounts the router; the incumbent `app/shell.tsx` cascade and its `Surface` navigation are dismantled onto routes, the store, and the data hooks. Existing screens (front door, project detail, settings, context map, review workspace) stay reachable and functional — rebuilt properly in their own C-changes.

## Reconciliations against main (packet drift, recorded per the dispatch rule)

1. **Incumbent measurements.** The packet (via client asset §2) says `shell.tsx` is 3,150 lines with ~25 invoke-effects. At HEAD it is 1,087 lines with 12 direct `invoke` sites; roughly the same count again lives in nine component files (`settings-screen`, `front-door`, `project-detail`, `github-connect`, `connection-host`, `context-map-view`, `project-processing`, `pr-worktree-status`, `directory-browser`). The anti-pattern is intact, just distributed across 10 legacy files. The migration of those sites is NOT done in this change — it is deferred to each surface's rebuild (C03/C10/C11/C12, task 4.6). Instead the seam is enforced by an armed lint fence with those 10 files in an explicit quarantine (reconciliation 5).
2. **Two incumbent screens have no #480 row.** The `Surface` kinds `projects` (front door) and `project` (project detail) predate the #480 grammar, which has no project-list or project-detail route. URL grammar beyond #480 is out of scope, so these mount at interim routes that keep them reachable but are not part of the documented URL contract; their permanent addresses are settled by the changes that rebuild them (C12/C3). Flagged, not resolved.
3. **Slice list supersession.** #480's resolution text names slices `ui`/`sidebar`/`run`/`review` (the spike). The packet supersedes it: `ui`/`review`/`run`/`signal`, no `sidebar` slice. The packet wins; this is the decided target, not a re-opening.
4. **Session slugs before sessions exist.** `/s/:slug` presumes #466 durable-session identity, which lands with B3/B9. Until then the slug resolves against today's review/project commands (packet: "runs against existing commands; board-shaped queries stub until B3"), via one resolution helper in `routes/` so the B9 swap is one file.
5. **Lint armed via strangler quarantine, not full migration first.** Tasks 2.7/4.6 originally planned to arm the `.invoke` ban only after migrating all ~47 incumbent sites. This change inverts that: the fence is armed NOW (`eslint.config.mjs`, `no-restricted-syntax` on `CallExpression[callee.property.name='invoke']` over `app-ui/src`), with the 10 legacy files held in an explicit, per-workstream-annotated `ignores` quarantine. The seam is enforced law for all new/rebuilt code immediately; each surface rebuild deletes its quarantine line, and C14 conformance verifies the list is empty. Zero silent grandfathering — the exceptions are a tracked list, not an open hole. Positive control: `invoke-lint.test.ts` + a real-config probe (deleted after capture).
6. **`nav/history.ts` retired incrementally, not deleted.** The packet says "retire it". Deleting it now would red the gate — 3 legacy importers remain (`app/shell.tsx` + `components/breadcrumb.tsx` → C03; `command/commands.ts` → C11). It is superseded by the injected-history router (`routes/`) and now carries a DEPRECATED header naming `routes/` as the go-forward navigation seam; it is dropped incrementally as those surfaces rebuild. Retirement is a process here, not a single delete.

## Out of scope (packet)

Any surface (C3–C13 own their rebuilds; this change only keeps incumbents functional through the cutover). URL grammar beyond #480. Porting spike state code — autopsy S1/S3/S9 are the anti-patterns this change exists to prevent, not import.
