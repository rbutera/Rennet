## 2. The data seam — `app-ui/src/data/`

- [ ] 2.1 **Cache decision** (packet-mandated): evaluate `@tanstack/react-query` against `docs/developing/reference/dependency-standard.md`'s admission test — subsystem removed (request dedupe, stale tracking, invalidation — the ~400 lines we would get subtly wrong), source health, licence (MIT), overlap (zustand owns interaction state, not the server-projection cache — no owner conflict), boundary fit (browser-safe, `app-ui`). Record the verdict where dependency decisions live (baseline table update lands with cluster 5's docs). If **adopted**: exact version pin in `packages/app-ui/package.json`. If **rejected**: the fallback in 2.3. Either way the hook signatures below are the contract — the choice must be invisible outside `src/data/`.
- [ ] 2.2 `data/bridge.tsx`: `BridgeProvider` + `useBridge()` over React context. `RennetApp` receives the bridge once at mount; no component receives it as a prop.
- [ ] 2.3 `data/query.ts`: `useCommand(name, input, opts) → {data, error, pending, stale}`. Cache key = command name + canonically serialized input (stable key order). Backed by react-query (query fn = `bridge.invoke`) or, if rejected in 2.1, a module-level `Map` + `useSyncExternalStore` (~120 lines: dedupe in-flight, stale flag on invalidate, per-key subscribers) — same signature.
- [ ] 2.4 `data/stream.ts`: `useCommandStream(channel, key)` — subscribes the named push channel on the bridge and folds each event into the matching `useCommand` cache entry (react-query `setQueryData` or the fallback cache's write), so components read one cache entry, never a second event state.
- [ ] 2.5 `data/mutate.ts`: `useMutation(name) → {mutate, pending, error}` — `bridge.invoke` then invalidate by key prefix (the command names whose reads it stales, declared at the call site).
- [ ] 2.6 Hook tests over `MemoryBridge`: two components sharing a `useCommand` key produce one invoke (dedupe); a streamed event lands in the read's `data`; a mutation invalidates its declared prefix and the read refetches; an invoke rejection surfaces as `error`, not an unhandled throw.
- [ ] 2.7 **The standing law as lint**: an `eslint.config.mjs` rule scoped to `packages/app-ui` (e.g. `no-restricted-syntax`/`no-restricted-imports` matching `.invoke(` member calls on a bridge outside `src/data/`, plus banning `data/bridge`'s raw bridge escape outside `src/data/`) so a component calling `bridge.invoke` directly **fails lint**. The rule ships in this cluster but the repo only goes clean after cluster 4's migration — scope it to `src/data/`-external files and keep the gate green by landing it disabled-nowhere: if the migration order forces it, land the rule in 4.6 instead; zero grandfathered exceptions either way.
