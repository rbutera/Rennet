## 2. The data seam — `app-ui/src/data/`

- [x] 2.1 **Cache decision**: `@tanstack/react-query` REJECTED against the admission test. Verdict: the need is three hooks over a keyed store (dedupe in-flight, stale-on-invalidate, per-key subscribers); react-query's surface (refetch-on-focus, GC, retries, devtools, infinite queries) far exceeds it and would need configuring-off, so it fails "removes a subsystem Rennet would otherwise maintain" at the size that matters. The owned `CommandCache` (~130 lines, `data/cache.ts`) is browser-safe, fully controlled, and invisible outside `src/data/` (same hook surface). Docs baseline table updated in cluster 5.
- [x] 2.2 `data/bridge.tsx`: `BridgeProvider` + `useBridge()` over React context; one `CommandCache` per provider. `RennetApp` receives the bridge once at mount; no component receives it as a prop.
- [x] 2.3 `data/query.ts`: `useCommand(name, input, opts) → {data, error, pending, stale}`. Cache key = command name + canonically serialized input (`stableStringify`, sorted keys). Owned `Map` + `useSyncExternalStore` (`data/cache.ts`): dedupe in-flight, stale flag on invalidate, per-key subscribers.
- [x] 2.4 `data/stream.ts`: `useCommandStream({channel, subscriptionKey, command, fold})` — subscribes the keyed push channel (progress / projectDetailProgress / askStream) and folds each event into the matching `useCommand` cache entry via `cache.setData`, so components read one cache entry, never a second event state.
- [x] 2.5 `data/mutate.ts`: `useMutation(name, {invalidates}) → {mutate, pending, error}` — `bridge.invoke` then invalidate by key prefix (command names declared at the call site).
- [x] 2.6 Hook tests over `MemoryBridge` (`data/data.dom.test.tsx`): dedupe (two readers → one invoke); a streamed event lands in the read's `data`; a mutation invalidates its declared prefix and the read refetches; an invoke rejection surfaces as `error`.
