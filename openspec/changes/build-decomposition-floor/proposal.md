## Why

Every angle a fleet emits (#8) sits on top of a decomposition of the change, and that decomposition cannot depend on a model being present, authenticated, or correct. It has to exist offline, with zero model calls, as the always-present floor under the hybrid (Contracts R9): the deterministic pass owns totality, classification, and the size budget, and it is the ONLY admission authority for verified noise. This slice builds that floor over a captured `Patchset` — mechanical-vs-substantive classification, `file → symbol` grouping, greedy chunking to a ≤400 changed-LOC budget with oversize-hunk splitting (R18), and the code-dependency DAG plus its topological reading order. That DAG order is the deterministic ordering BASELINE the agent comprehension-ordering pass (#9) reads through; ordering here is LOGICAL / dependency-based, never danger / blast-radius / salience (Contracts §1, correction 8). The floor is the floor, not the semantic authority.

## What Changes

- Add the decomposition data types to `packages/types` (import-nothing): the `MechanicalClass` closed vocabulary, the `Hunk` (with `splitOf` on an oversize fragment), the per-hunk `HunkClassification` (kind + mechanical class + `""`-degrading `enclosingSymbol`), the `DecompositionChunk` (substantive / appendix, layer, budgeted LOC), the `DecompositionEdge` (`enables` and the richer agent-proposed kinds), the always-empty-from-the-floor `DecompositionResidueItem`, and the top-level `Decomposition`.
- Add the deterministic floor to `packages/core` (`decompose`): a pure function of the patchset — no network, model, clock, or filesystem — that is byte-stable across two runs. It parses hunks from each file's patch, classifies every hunk (lockfile / vendored / generated by path-or-marker / pure-rename / mode-only / formatting-only, else substantive), splits any oversize substantive hunk so the ≤400 budget holds, groups `file → enclosingSymbol` and greedy-merges to the budget, routes mechanical hunks to per-file appendix chunks, derives `enables` edges from resolved relative imports (dropping any edge that would close a cycle so the stored graph is a DAG), and linearises the DAG with a deterministic layer/path tiebreak.
- Add the `SymbolExtractor` port with a degraded default that returns `""` for every hunk (group by file alone). The real tree-sitter enrichment (parse-once-dispose, an adapters/native concern) is a follow-up; a missing grammar never blocks the floor.

## Capabilities

### New Capabilities

- `decomposition-floor`: The deterministic, offline, zero-model decomposition of a patchset — classification, chunking to the ≤400 budget with oversize splitting, the dependency DAG, and the topological reading-order baseline — that renders with no harness installed and no network.

### Modified Capabilities

None.

## Impact

- Adds `packages/types/src/index.ts` decomposition types and `packages/core/src/decomposition.ts` (re-exported from `@rennet/core`) plus its colocated test. No new production dependency; the floor is pure computation over the existing `Patchset` shape.
- Deferred to follow-up beads (issue #7 is a slice of umbrella `workspace-3svrc`): the tree-sitter `SymbolExtractor` implementation in `packages/adapters` (parse-once-dispose per file); mapping the floor's native `Decomposition` onto the RSP `decomposition.skeleton` / `decomposition.proposal` documents with `rennet:` anchors and a `route: deterministic` provenance block; richer binary / submodule / truncated-input handling (R18); and an end-to-end `GitCaptureAdapter` → `decompose` integration test over a real temporary repository.
