Live lenses — low-fidelity wireframes

Boxes and labels, monochrome, no styling and no motion. Each file is self-contained: open it in a browser, no build, no server.

The model these draw

A round runs five lens seats — Design, Sequence, Decisions, Flagged, Noise — and each is its own coding-agent thread with its own transcript. Flagged has two voices, a Claude seat and a Codex seat, which means two threads writing findings onto one Flagged board. There is no single transcript for a round; there are six.

The direction being drawn: a board exists before its seat starts, and the seat writes elements into it as it works (add_step, cite, add_finding, finish) instead of returning one JSON blob at the end. So a board fills in element by element while the reviewer watches, a finish can come back with a lint pointer the seat then answers, and every board element has a matching receipt in its seat's transcript.

Each option shows all of that at once: the five lanes with Flagged's two voices, one lane selected, that lane's Sequence board mid-draft (steps arriving, a citation attaching, a finish that returned one lint pointer), and that same lane's transcript beside it. Board elements and transcript receipts are tied by the letters a–d; in a built version that is a shared highlight on hover plus a one-shot pulse as an element lands.

What 0.7.0 does today

During generation the preparation bench shows five readers and renders each settled board below them, stacked in lane order in one column (packages/app-ui/src/app/preparation-bench.tsx). Two problems: the column outgrows its pane, and nothing on a landed board says it is provisional or which seat is still working. Every option below is measured against fixing both.

Options, in preference order

1Boards first, agent widget above the board

No bench as a separate stage. The review opens on the board view; the lens tabs carry working indicators; the selected board draws itself while you watch, with a prominent widget above it naming the seat doing the work — provider, model, elapsed, what it is doing right now — that opens the live transcript on click and collapses to a receipt line when the lens settles. Draws both transcript variants: the chat dock, and a drawer under the widget.

2Transcript in the chat dock (current architecture)

Bench compressed to a rail with the board under it; the seat's transcript takes over the existing chat dock. Cheapest to build — the bench already routes a voice to the dock — but it keeps the bench as a stage above the board, so two surfaces claim to say which lens you are on.

3Bench rail, board left, transcript right

The main region splits under a five-column bench rail; the chat dock keeps the review's own conversation, so the orchestrator stays visible. The transcript is always on screen rather than a click away, which costs the board half its width and needs a live thread view mounted outside the chat dock.

4Per-lane drawer on the bench

The bench keeps the whole main region and the selected lane expands in place, board and transcript together inside the drawer. Reads well while all five are running and badly once you only want to read one finished board, and it makes the board a narrow nested surface.

5Tabbed transcript strip under the board

The board owns the main region; the bench becomes a bottom strip of six tabs (Flagged is two), the selected one filling the strip with its live transcript. Same boards-first instinct as option 1, but it spends permanent vertical space and turns the bench into chrome instead of folding it into the tabs the shell already has.

Where the costs come from

Each option's last section costs itself against three real places in the shell:

  • packages/app-ui/src/app/preparation-bench.tsx — the five-lane bench. It already models per-seat voices (voicesOf names them Claude/Codex when a lane has more than one seat), already makes every reader a control that calls uiActions.openLensThread, and already renders settled boards through LensBoardDocument.
  • packages/app-ui/src/chat/t3-chat-dock.tsx — the chat slot. It is the single mount of the T3 thread view and already renders a lens seat's thread read-only when ui.lensThread is set. Any option that puts a live transcript somewhere else needs a second mount, which does not exist today.
  • packages/app-ui/src/shell/top-bar.tsx and packages/app-ui/src/board/lens-switcher.tsx — three slots (back/chat-toggle/trail, the centred lens switcher, the History · Map · Diff pills). The switcher currently lists only lenses with a terminal result, so any option that wants a running lens to be selectable changes what the switcher is for.
