What is where

There is no separate bench screen. The review opens on the board view it will end on: the existing lens tab bar at the top, the board below. Each tab carries the state of its seat — a spinner while it runs, a check when it settles, a cross when it fails, a dash when the lens is absent, and Flagged carries two indicators because it has two voices. The tab bar is the bench; the five lanes are the five tabs.

Directly above the board sits the agent widget for the seat drafting this lens: provider and model, elapsed time, a live line of what it is doing right now, and a count of what it has written so far. The board underneath is marked provisional in three independent ways, so the state is unmistakable: the tab spins, the board header carries an in progress chip and says the board is still being written, and the last row is a ghost saying the next element lands there. Elements and receipts are tied by the letters a–d; in a built version that is a shared highlight, plus a one-shot pulse as an element lands.

On click

Clicking the widget opens that seat's full transcript, updating live. Two variants are drawn: (i) it fills the existing chat dock, which is what the shell already supports, or (ii) it opens as a drawer under the widget and pushes the board down, leaving the chat dock on the review's own conversation. Clicking a lens tab switches board, widget and transcript together — one control, three panes, no way for them to disagree. On Flagged, the widget shows both voices side by side and each has its own “Open transcript”; the board is shared. When a lens settles, its tab stops spinning and its widget collapses to a one-line receipt (who drafted it, how long, what it produced, a link to the transcript), which stays as the way back into the thread. The board header's in-progress chip and the ghost row both clear. Nothing navigates: the drafting view and the finished view are the same view.

Cost against the current shell

Medium, and different in kind from the other four: it deletes a screen rather than adding one. packages/app-ui/src/app/preparation-bench.tsx stops being the first frame; its five-reader scene, its slab and its capture rail either move into the tab indicators and the board header or go away. That is a large deletion in a file that is mostly presentation, and its lane model (voicesOf, per-seat thread refs, the Register states) is exactly what the tab indicators and the widget need, so the data layer survives intact.

packages/app-ui/src/board/lens-switcher.tsx gains a per-segment state indicator. It currently renders one segment per lens that produced a terminal result (useLensBoards; a lens with no terminal result is simply absent, never disabled), so this option needs the switcher to list every lane the daemon has opened, including running ones — a real change to what the switcher is for. packages/app-ui/src/shell/top-bar.tsx keeps its three slots as they are.

The board document has to render a partial board and say so. Variant (i) is nearly free — uiActions.openLensThread and the dock's slot.thread … readOnly path already exist. Variant (ii) needs a live thread view mounted outside t3-chat-dock.tsx, which is today the single mount of the T3 slot.

What 0.7.0 does today, and what this fixes

Today the bench draws the five readers and then renders every settled board below them, stacked in lane order inside max-w-4xl (preparation-bench.tsx, “THE BOARDS THAT HAVE LANDED”). Two things go wrong. The column grows past its pane, and the bench's own comment records an earlier version of this bug — plain centring pushed the slab and the first readers where no scroll could reach them. And nothing on a landed board says it is provisional or which seat is still working, so a board that is one repair away from being redrawn reads exactly like a finished one. This option answers both: one board on screen at a time, chosen by a tab; the working state said three times on the surface you are actually reading; and the finished view is the same view with the chips gone.
